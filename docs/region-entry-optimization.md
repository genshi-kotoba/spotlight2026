# 地区入场等待优化

本次仅调整正式四层入口与显示缓存，不改变地图拓扑、随机流、战斗规则或地区首次记录。

## 原因与行为

原入口把“当前几何可以操作”和“未来探索状态的显示缓存全部预建完成”当作同一个条件。切层黑场结束后，后台仍为路线门之后的状态构建几何、太阳阴影、材质和网格，移动与地区标题都继续等待。

正式入口现在以当前地图几何完成、显示准备已提交、入场淡入结束为准，开放角色并播放标题。后续探索变体继续后台预热。新发起的路线门交互仍需完整缓存就绪；过早接近时提示“前方区域正在准备，请稍候再进入”，不创建 pending、不取消任务，角色继续可移动。普通节点保持原流程。独立地图 demo 仍沿用原有完整缓存就绪条件。

读档已有 pending 路线战斗的自动恢复行为保留；它是既有流程，另以独立进程恢复战斗、领奖和返回地图验证。

## 减少重复计算

太阳阴影投影以精确 caster 顶点/边、接收平面、太阳方向、basis、像素比例为身份，跨探索状态复用原样投影及 bounds。沿用原裁剪顺序和浮点算法，不减少阴影片段、不更换三角化、不舍入几何。缓存受同一 mutex 保护，上限 20,000 行和 128,000 顶点；满额回退本地计算。清空时几何和配置 ID 不复用，迟到任务不能命中新状态。

预热线程使用低优先级，当前几何任务保持正常优先级；后台网格提交采用批次间 2 ms 软预算，当前几何仍为 6 ms。单个 batch 不会被截断。相关 API 参见 [Godot Thread 文档](https://docs.godotengine.org/en/stable/classes/class_thread.html)。

渲染报告补充 input_load、atmosphere、art、fog、materials、worker_total，补齐原 total 未覆盖的阶段；worker_total 不包含主线程输入装配与 GPU 提交。

## 验证范围与限制

证据位于工作区 `output/region-entry-optimization-20261020/`：原生入场空窗采样、键盘移动、早到路线门、后台完成后真实入战、pending 路线战斗独立进程恢复，以及多种子的几何/阴影/三角形对照。

原生流程使用真实地图、标题、战斗与奖励界面；接近路线门时使用夹具瞬移，战斗以 QA 调试胜利推进，不代表自然通关。并发缓存测试覆盖精确平面区分、结果不可变、clear 后迟到任务、重复写入及容量边界。测试使用隔离存档，不访问玩家进度。

本次消除已出图后的全缓存等待，并不代表冷启动、地图生成或当前几何构建已经零耗时。CPU 负载会影响耗时；阶段数据用于定位，不能把一次采样当作所有机器上的固定时长或稳定加速比。

2026-10-20 原生同种子前两层对照：原第二层可见地图空窗为 10,288 ms，优化后两层均未采到该空窗。此夹具保持未暂停以排除操作系统焦点干扰，指标不含冷加载时间。四个楼层、三个随机种子共 11 个探索状态的面数据（含阴影）散列和三角形数量逐项一致；第四层为固定布局单状态。
