# 统一场景加载提示

场景切换统一调用自动加载节点 `SceneTransition`。主菜单、档案、图鉴/成就返回、地图进入战斗、领奖后返回地图、战斗返回菜单、典籍测试和正式卡牌测试重开均已接入。

```gdscript
var error := SceneTransition.change_scene_to_file("res://ui/main_menu/main_menu.tscn")
if error != OK:
    # 同步校验或重复请求失败，在原界面提示。
    push_warning("无法开始切换：%d" % error)
```

`OK` 代表请求受理，不代表异步加载已经完成。可监听 `transition_started(path)`、`transition_finished(path)`、`transition_failed(path, error)`，或调用 `is_loading()` 查询。新入口不要直接调用 SceneTree 的换场景方法，以免绕过遮罩。

## 显示和交互

- 自动加载 CanvasLayer 跨场景保留，层级 2048，高于普通 UI 和嵌入弹窗。
- 旧场景约 0.12 秒淡出至全黑，准备好后新场景约 0.16 秒淡入；移除正常转场中的文字、底框和省略号动画。
- 保留已有菜单／节点资源预热；全黑真正绘制后再请求尚未缓存的场景资源并替换场景。准备期间保持黑屏，不提前展示未完成的地图，也不额外添加阅读等待。
- 加载中暂停场景树、拦截鼠标/键盘并接管焦点。一般重复请求返回 `ERR_BUSY`，不会并行切换。
- 新场景完成 `_ready`、延迟初始化与首帧布局后才开始淡入；淡入完成再解除操作锁并恢复原先暂停状态，旧焦点仍有效时恢复它。
- 连续跳转在准备阶段共用全黑遮罩，只淡入最终场景；已开始淡入时的新切换请求返回 `ERR_BUSY`。
- 载入/准备失败时也会淡入并解除加载锁，保留可关闭错误提示；无效路径同步拒绝。准备阶段有 120 秒超时保护。
- `last_metrics` 的 `fade_out_ms`／`fade_in_ms` 单独记录动画耗时；`total_ms` 包含淡入淡出，不把视觉变化称作后台计算提速。

## 地图与战斗准备

地图除了实例化，还需要等待地形工作线程和显示缓存。加载期间只临时让纯表现层 `MapPresentation` 继续处理，玩法仍暂停；根据地图现有的 `is_map_ready()` 判断完成，避免暂停后地图工作无法收尾。

正式战斗提供 `is_scene_transition_ready()`，等待开局逻辑与延迟 UI 刷新。开局仍使用原有战斗事件队列，不重复创建战斗或消耗玩法随机流。新场景准备中若因读档/无效入口立即跳向战斗或主菜单，会继续使用同一遮罩，不在中间场景短暂放开操作；最多允许连续 8 次跳转。

其他异步准备场景可实现 `is_scene_transition_ready() -> bool` 和可选的 `scene_transition_error() -> String`。准备工作应使用后台线程、延迟调用或独立的纯表现处理节点，不应依赖已暂停的玩法 `_process()`。
