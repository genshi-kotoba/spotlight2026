# 07 · 开始界面与设置说明

开始界面、切换档案、设置、占位跑图四个场景的实现说明。接入步骤、美术资源替换与约束见 `docs/08-开始界面与设置交付说明.md`。规格来源是 `docs/prompts/PRG-016-021-开始界面与设置.md`。

## 一、场景与脚本

| 文件 | 职责 |
| --- | --- |
| `ui/main_menu/main_menu.tscn` + `.gd` | 开始界面：标题、六个按钮、右上角当前档案、右下角版本号；场景内挂确认弹窗与提示条 |
| `ui/main_menu/profile_switch.tscn` + `.gd` | 切换档案：三张档案卡片，底部「切换档案」「删除存档」 |
| `ui/main_menu/slot_card.tscn` + `.gd` | 单张档案卡：槽号、状态、摘要、当前档角标 |
| `ui/main_menu/confirm_dialog.tscn` + `.gd` | 覆盖与删除共用的确认弹窗 |
| `ui/main_menu/message_bar.tscn` + `.gd` | 底部提示条，用于写盘或读档失败 |
| `ui/placeholder_run/placeholder_run.tscn` + `.gd` | 占位跑图场景，临时件，见 `docs/08` 第一节 |
| `ui/settings/settings.tscn` + `.gd` | 设置：三根音量滑条、全屏开关、分辨率下拉、返回 |
| `autoload/save_gateway.gd` | 唯一读写存档的文件，见第五节 |
| `tests/main_menu_selftest.gd` | 自测，见第七节 |
| `project.godot` | `[autoload]` 登记 `SaveGateway`；`run/main_scene` 指向开始界面 |

沿用 `docs/01-项目结构与目录约定.md` 的约定：一屏一场景，场景与脚本一一对应；几何与字号写在 `.tscn`（锚点加偏移、`theme_override`），脚本不设 `position`、`size`、`font_size`；界面只调 `SaveGateway` 并只听它的信号，不直接读写存档文件与状态机；依赖方向为 `ui → systems → state_machines → core`。

## 二、运行

- 编辑器：按 F5 运行主场景，即开始界面；单独查看某一屏，打开对应 `.tscn` 按 F6。
- 命令行：在仓库根目录执行
  `"D:\mod\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe" --path .`
  PATH 上的 `godot` 指向失效路径，不使用。
- 屏间跳转：开始界面右上角「当前档案 N ▾」进切换档案，「设置」进设置，「新游戏」「继续游戏」进占位跑图；设置屏的「返回」、切换档案屏的「切换档案」、占位跑图的「回主菜单」回到开始界面。

## 三、界面改法

| 目标 | 位置 |
| --- | --- |
| 标题文字与字号 | `main_menu.tscn` 的 `标题` 节点：`text`、`theme_override_font_sizes/font_size` |
| 六个按钮的尺寸与间距 | `按钮列`（VBoxContainer）的 `theme_override_constants/separation`；各 Button 的 `custom_minimum_size` |
| 右上角档案按钮的位置 | `档案` 节点的锚点与偏移，`grow_horizontal = 0` |

| 档案卡片的尺寸与文字位置 | `slot_card.tscn` 的 `档案卡`（`custom_minimum_size`），`槽号`、`状态`、`摘要`、`当前标注` 四个 Label 的偏移 |

## 四、档案卡片三态

| 状态 | 判定 | 卡片显示 |
| --- | --- | --- |
| 空 | 该档没有存档文件 | 槽号 +「空」+ 破折号 |
| 进行中 | 该档有文件，且 `active_run` 或占位标记非空 | 槽号 +「进行中」+ 区域 + 生命 + 金币 + 上次游玩（占位局无快照时以进度替代生命与金币） |
| 已结束 | 该档有文件，但没有进行中的局 | 槽号 +「已结束」+ 区域 + 对局数 + 上次游玩 |

「已结束」是死亡或舍弃之后的档案状态，不是空档：解锁与对局记录保留，可直接在该档开新局。清空档案只发生在玩家确认「删除存档」时。

卡片右下角的「当前档案」标的是当前生效的档；卡片的选中描边标的是即将切换过去的档。两者含义不同。

## 五、SaveGateway 契约

`SaveGateway` 是 autoload。方法名、信号名与 `list_slots()` 的字段名固定，`ui/` 只使用这一套。方法分两类：转发（与状态机同名同形，接入后直接转发）与网关自有（状态机不提供）。

| 方法 | 归属 | 说明 |
| --- | --- | --- |
| `list_slots()` | 网关 | 三档信息，字段见下 |
| `get_active_slot()` / `set_active_slot(slot)` | 网关 | 当前档存在全局文件；切换后发出 `active_slot_changed` |
| `has_continuable_run()` | 转发 | 当前档有无进行中的局 |
| `start_new_run(seed_text, config)` | 转发 | 开新局；已在局中时状态机返回 `ERR_ALREADY_IN_USE` |
| `continue_saved_run()` | 转发 | 继续存档中的局 |
| `abandon_run()` | 转发 | 舍弃本局 |
| `set_run_progress(progress)` | 网关 | 占位专用，接入状态机时删除 |
| `delete_slot(slot)` | 网关 | 删除该档 JSON 与其 `.tmp`、`.bak` |
| `get_setting(key, default)` / `set_setting(key, value)` | 网关 | 全局设置文件，不转发状态机 |
| `list_achievements()` | 网关 | 全局成就，供 PRG-020 |
| `list_unlocked_cards()` / `list_run_history()` | 网关 | 读取当前档 JSON，接入后转发状态机 |
| `quit_game()` | 网关 | 先落盘再 `get_tree().quit()` |

`list_slots()` 每一项的字段：`slot`（int，1–3）、`exists`（bool）、`state`（`"empty"` / `"active"` / `"ended"`）、`region`、`health`、`max_health`、`gold`、`progress`、`run_count`、`updated_at`。

信号：`slots_refreshed`、`active_slot_changed(slot)`、`run_started(slot)`、`run_continued(slot)`、`save_failed(error, message)`、`settings_changed(key, value)`。方法执行后发出信号，界面只监听信号。

### 存盘文件

文件位于 `user://save/`：

| 文件 | 内容 |
| --- | --- |
| `slot1.json` / `slot2.json` / `slot3.json` | 一份档案。接入状态机后即状态机的存档文件，内容为 `save_version`、`settings`、`achievements`、`unlocked_cards`、`run_history`、`active_run` |
| `settings.json` | 网关自持的全局文件：当前档索引、五个设置项、成就列表 |

写盘先写 `.tmp`，再换名为正式文件，原文件留为 `.bak`。写盘前调用 `DirAccess.make_dir_recursive_absolute("user://save")`；状态机的 `_write_atomic()` 不建目录，缺少这一步会导致首次自动存盘直接 `save_failed`。

档案 JSON 中的 `placeholder_run` 是状态机接入前的临时替身，记录本局进度：`start_new_run()` 写入（进度从 0 起），`abandon_run()` 删除，`set_run_progress()` 更新进度，`read_slot()` 见到该标记即判为「进行中」并报出进度，`continue_saved_run()` 见到该标记即返回 OK。接入时这几处与 `set_run_progress()` 一并删除。

JSON 没有整数类型，读写一轮后整数会变成浮点：`read_slot()` 对生命、金币、对局数显式 `int()`，`_load_settings()` 用 `_restore_setting_value()` 把整数形态的浮点还原为 `int`。

设置与成就为全局数据，不随档案：删除某一档案不影响音量、全屏与成就。

## 六、状态流转

界面只负责询问与呈现：有无可继续的局问 `has_continuable_run()`，开局调 `start_new_run()`，继续调 `continue_saved_run()`，舍弃调 `abandon_run()`。局内状态 `active_run` 由 PRG-002 的 `GlobalState` 写入；占位期网关写入的是自持的 `placeholder_run` 标记。界面脚本中不出现 `active_run`，`tests/main_menu_selftest.gd` 有两条断言维持这一点。

「新游戏」分三种情况（`main_menu.gd`）：

1. 当前档为空：直接开局。
2. 当前档有进行中的局：弹出「覆盖档案 N？」，确认后先 `abandon_run()` 再开局。
3. 状态机返回 `ERR_ALREADY_IN_USE`：再次弹窗，提供「继续游戏」与「舍弃本局后新开」。

开局后切换到的场景由 `main_menu.gd` 的 `@export var game_scene` 指定，当前为占位跑图场景 `res://ui/placeholder_run/placeholder_run.tscn`。

## 七、自测

在仓库根目录执行（使用第二节的 console 版可执行文件）：

```
--headless --path . --import                                    预期退出码 0，无 ERROR 与 WARNING
--headless --path . --script res://tests/main_menu_selftest.gd  预期输出「全部通过」，退出码 0
--headless --path . --script res://tests/card_effect_selftest.gd
--headless --path . --script res://tests/map_selftest.gd        确认未影响其他模块
```

`main_menu_selftest.gd` 覆盖：六个按钮文案、标题与版本号、当前档案显示、继续游戏的置灰与可点、`list_slots()` 的三态与字段类型、`set_active_slot()` 的信号、卡片选中态唯一、覆盖与删除确认的确认与取消、设置读写与读回类型、目录自动创建、`save_failed` 触发、占位跑图的闭环（含进度读回），以及第六节的两条状态机断言。测试向 `user://save` 写入假档案，运行前备份整个目录，结束后还原。

手动验证（编辑器按 F5）：

1. 开始界面「继续游戏」为置灰状态。
2. 点「新游戏」进入占位跑图，进度每 2 秒 +1。
3. 点「回主菜单」，开始界面「继续游戏」可点；切换档案屏显示该档为「进行中 · 进度 N」。
4. 点「继续游戏」回到占位跑图，进度从 N 继续。
5. 点「放弃本局」，「继续游戏」重新置灰，该档显示「已结束」。
