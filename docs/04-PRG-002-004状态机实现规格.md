# PRG-002—004 状态机实现规格

> 状态：编码前冻结版
> 日期：2026-10-05
> 来源：`策划案.md`、资产分配表中 PRG-002 / PRG-003 / PRG-004、已合并的地图与随机种子系统。

## 一、不可偏离的原始约束

### PRG-002 全局状态机

- 管理局外存档、成就、设置、卡牌解锁和历史对局记录。
- 对局记录至少保存牌组、通过的关卡数、死亡位置或胜利结果。
- 存档使用 JSON；游戏启动时自动读取，每局结束和游戏关闭时自动保存。
- 用布尔状态表示是否存在进行中的对局；继续游戏时恢复局内状态。
- 局内初始化只能把已经解锁的卡牌加入本局卡池。
- 监听局内数值更新并发起成就检查。

### PRG-003 局内状态机

- 管理地图、玩家状态、牌组、道具及单局进度。
- 新游戏时将对局状态设为进行中并初始化随机种子、地图、奖励池、商店池和事件池。
- 玩家死亡、胜利或主动舍弃存档时结束本局。
- 保存并更新：当前／最大生命、金币、牌组、道具、经历战斗数、击败敌人、每个地图节点状态。
- 所有可能触发成就的数值更新都要释放信号给全局状态机。

### PRG-004 战斗状态机

- 管理玩家、怪物、Buff、抽弃牌和怪物行动模式。
- 抽牌、弃牌、牌效和 Buff 都逐个结算，每一步都发出信号。
- 玩家回合顺序：抽牌 → Buff 结算 → 编排／出牌 → 指针逐张结算牌效。
- 敌方回合顺序：决定行动 → Buff 结算 → 执行动作。
- 抽牌堆为空时，把弃牌堆洗回抽牌堆；洗牌必须使用本场战斗的确定性随机流。

## 二、职责边界

| 模块 | 负责 | 不负责 |
|---|---|---|
| `GlobalStateMachine` | 局外数据、JSON、当前局快照、继续游戏、对局历史、解锁、成就完成状态 | 具体成就判定内容、地图生成、战斗规则 |
| `RunStateMachine` | 单局业务数据、池初始化、地图节点状态、玩家资源、战斗统计、局结束 | 写文件、界面、具体地图表现、具体奖励抽取 |
| `BattleStateMachine` | 回合阶段、牌堆、顺序结算、玩家／敌人战斗数值、通用 Buff 容器 | 具体卡牌效果、具体 Buff 效果、美术动画 |
| `SeedService` | 主种子、稳定地址随机流、随机快照 | 保存业务生成结果、决定业务 ID |

卡牌效果与 Buff 效果尚属 PRG-007 / PRG-008。本次状态机只负责**确定顺序、持有状态、发出请求与结果信号**，不虚构策划未定义的效果。

## 三、所有权与生命周期

```text
GlobalState（Autoload）
└── current_run: RunStateMachine（有继续游戏时才存在）
    └── current_battle: BattleStateMachine（处于战斗时才存在）

SeedService（Autoload，与 GlobalState 同生命周期）
```

1. 启动时 `GlobalState` 从 JSON 读取局外数据和未完成对局快照，但不立即创建业务场景。
2. 新游戏由 `GlobalState.start_new_run()` 创建局内状态并调用一次 `SeedService.begin_run()`。
3. 继续游戏由 `GlobalState.continue_saved_run()` 先恢复随机快照，再恢复局内／战斗业务快照。
4. 地图、战斗、商店等模块不得调用 `begin_run()`；它们只取得各自稳定地址的流。
5. 一局结束后全局状态机归档对局记录、清除继续游戏快照并保存 JSON。

## 四、稳定身份和随机地址

| 用途 | 随机域 | IDs |
|---|---|---|
| 地图节点 | `map.nodes` | `[map_id]` |
| 奖励池初始顺序 | `reward` | `[run_id, "pool"]` |
| 商店池初始顺序 | `shop` | `[run_id, "pool"]` |
| 随机事件池初始顺序 | `event.pool` | `[run_id, "pool"]` |
| 初始抽牌堆／弃牌堆重洗 | `battle.draw` | `[map_id, node_id, battle_index]` |
| 怪物行动选择 | `battle.logic` | `[map_id, node_id, battle_index]` |

`run_id`、`map_id`、`node_id`、`battle_index` 都进入业务存档。界面打开、场景重载或鼠标预览不能增加次数或重新抽取结果。

## 五、数据约定

### 5.1 全局存档

- `save_version`
- `settings`：通用键值，不在本任务里发明具体设置项。
- `achievements`：成就 ID → 完成状态／完成时间；成就规则由后续数据提供。
- `unlocked_cards`：稳定卡牌 ID 数组。
- `run_history`：已结束对局摘要。
- `active_run`：空或 `{run_snapshot, seed_snapshot}`。

采用临时文件写入再替换正式文件。格式或版本无效时保留默认状态并报告错误，不把损坏存档解释成空白新档后自动覆盖。

### 5.2 局内快照

- `run_id`、`main_seed`、`active`、`result`
- 玩家生命、生命上限、金币
- 已解锁卡池过滤后的 `card_pool`、当前 `deck`、`items`
- 地图 ID 列表、当前地图、每个节点状态
- `MapNodePlan.to_dictionary()` 生成的确定性节点计划；重进场景时直接恢复，不重抽
- 已初始化并保存的奖励池、商店池、事件池
- 经历战斗数、击败敌人 ID 列表、通过关卡数
- 当前战斗快照（若有）

### 5.3 战斗快照

- 战斗稳定身份与当前回合／阶段
- 玩家战斗数值、敌人状态
- 抽牌堆、弃牌堆、手牌、出牌区
- Buff 容器
- 指针位置与已结算次数

卡牌实例至少含稳定 `instance_id` 和配置 `card_id`。敌人至少含稳定 `enemy_id`、生命、最大生命、格挡和行动列表。

## 六、信号合同

### GlobalStateMachine

- `save_loaded`、`save_failed`
- `run_started`、`run_continued`、`run_finished`
- `achievement_check_requested(metric, value, run_snapshot)`
- `achievement_unlocked(achievement_id)`

### RunStateMachine

- `run_started`、`run_ended`
- `stat_updated(metric, value)`：全局状态机监听此信号发起成就检查。
- `map_node_updated`、`battle_started`、`battle_finished`
- `state_changed`

### BattleStateMachine

- 阶段和回合变化信号。
- 每次抽牌、弃牌、洗牌各自发信号。
- `card_effect_requested` 与 `card_resolved` 按指针顺序逐张发出。
- `buff_effect_requested` 与 `buff_resolved` 逐个发出。
- 怪物决定动作和执行动作逐个发出。
- 生命、格挡、Buff、胜负变化发信号。

普通结算同步且不在中途 `await`。监听者在请求信号返回前完成对应的同步效果；动画等待只属于表现层。需要玩家输入的效果使用显式确认协议：当前已提供 `discard_choice_requested` 与 `submit_discard_choice()`，状态机在 `PLAYER_EFFECTS` 暂停，收到合法选择后从原指针继续，不能靠计时器猜测。

## 七、状态流

### 玩家回合

```text
PLAYER_DRAW → PLAYER_BUFF → PLAYER_ACTION
                                 │ commit_player_sequence
                                 ▼
                         PLAYER_EFFECTS
                                 │ 指针到末尾
                                 ▼
                         ENEMY_DECIDE
```

### 敌方回合

```text
ENEMY_DECIDE → ENEMY_BUFF → ENEMY_ACTION → 胜负检查
                                             ├─ 未结束 → PLAYER_DRAW
                                             ├─ 敌人全灭 → VICTORY
                                             └─ 玩家死亡 → DEFEAT
```

指针允许牌效请求回跳，但每回合最多结算固定安全上限，防止构筑形成无限循环。安全上限只是故障保护，不替代后续策划对合法循环的正式定义。

## 八、失败策略

- 缺主种子、稳定 ID、合法牌组或敌人时，初始化失败且不创建半成品状态。
- 随机流取得或洗牌失败时中止当前初始化／结算，不切换到全局随机，也不静默生成默认结果。
- 非法状态转换返回 Godot `Error`，不继续执行后续阶段。
- 存档先整体校验再安装；失败不替换当前可用状态。
- 恢复随机快照成功而业务快照失败时，不允许继续游戏，由全局协调者保持暂停并报告错误。

## 九、验收清单

- 相同主种子与业务输入得到相同三类池顺序和初始牌堆。
- 只有解锁卡牌进入单局卡池。
- 生命、金币、战斗数、击败敌人和地图节点更新都会发出 `stat_updated`。
- JSON 往返后局外、局内、战斗业务状态一致；随机快照接续而不是重开。
- 抽牌堆为空时弃牌堆使用 `battle.draw` 原流洗回。
- 抽牌、Buff、卡牌、敌人行动严格按阶段逐个发信号。
- 指针回跳可重复触发前方卡牌，并受安全上限保护。
- 胜利、死亡、主动舍弃都结束本局；结束与关闭触发保存。
- 现有地图自测继续通过。

- `res://tests/card_battle_integration_selftest.gd`
- `res://tests/card_battle_integration_selftest.tscn`

开始新局时只调用全局入口；配置内容来自后续数据资产，不由状态机硬编码：

```gdscript
var error := GlobalState.start_new_run(seed_text, run_config)
if error != OK:
	push_error("创建新局失败：%d" % error)
```

进入战斗时由当前局创建并持有战斗状态机：

```gdscript
var error := GlobalState.current_run.start_battle(node_id, enemy_snapshots)
if error != OK:
	push_error("创建战斗失败：%d" % error)
```

战斗界面在 `PLAYER_ACTION` 阶段提交按显示顺序排列的卡牌实例 ID；PRG-007/008 监听请求信号并在信号返回前同步修改战斗数据：

```gdscript
var error := battle.commit_player_sequence(ordered_instance_ids, targets_by_instance_id)
```

读档只调用 `GlobalState.continue_saved_run()`。调用方不得自行恢复随机快照、重新生成地图节点或重新洗牌。

无渲染验收命令：

```bash
godot --headless --path . --scene res://tests/state_machine_selftest.tscn
godot --headless --path . --scene res://tests/card_battle_integration_selftest.tscn
```

状态机自测覆盖解锁卡池过滤、三地图与三类随机池初始化、局内／随机快照联合恢复、阶段顺序、指针回跳、Buff 逐项请求、弃牌重洗、跨牌区实例唯一性、初始终局判定，以及全局 JSON 存读档。卡牌战斗集成自测覆盖资源效果解析、攻击与中毒结算、同名 buff 合并、一次性卡移除、回合推进，以及恢复后继续结算资源卡牌。
