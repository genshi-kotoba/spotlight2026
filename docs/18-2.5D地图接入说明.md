# 2.5D 地图接入

正式入口仍是 `ui/main_menu/menu_map_entry.tscn`。主菜单的新局、继续、F6 地图入口均进入当前炼金工坊高低差地图。实现为 Node2D + 高度投影和深度排序，未引入 Node3D 物理世界。

## 团队接线

| 层 | 负责范围 | 调用约定 |
| --- | --- | --- |
| `PlanarMapRun` / `PlanarMapSession` | 多层地图、节点、通行、碰撞、探索、请求令牌与状态快照 | 仍为二维六边形逻辑；高度不会增加或移除路线。 |
| `menu_map_entry.gd` | 局内状态、存档、交互路由 | 战斗 / 精英 / Boss → `EncounterFlow`；商店 → `RunShop`；奖励 → `RunRewards`。 |
| `relief_2d/map_exploration.gd` | 高度、投影、角色动画、光影、雾与局部墙体透明 | 使用 session 的真实可达域和 `collision_boundaries()`；不得另做一套碰撞。 |
| `MapPresentation` Autoload | 当前局、当前层的显示缓存 | 场景借用 renderer，退出时隐藏并暂停；战斗返回复用。不得存放生命、奖励或权威地图状态。 |
| `MapEvents` / `SaveGateway` / `SeedService` | 团队已有事件、持久化和随机流 | 接口保持；地图显示不重开主种子，不替换战斗持有的随机流。 |

地图移动、E 交互、Q 目标切换、鼠标左键持续移动、滚轮缩放，继续由公共地图装配处理。屏幕方向先反投影为逻辑平面方向，再交给原碰撞求解。背包、典籍、地图总览、设置及真实战斗界面保留。

`load_map()` 返回 true、收到 `map_loaded` 仅表示逻辑绑定已接受，不代表全部显示准备完成。显示准备未完成时，`is_map_ready()` 为 false，移动与地图交互暂缓；不要用“固定等待几帧”代替就绪判断。自动化接入者应重新取得当前 scene，检查它是否实现 `is_map_ready()`，再等待为 true；战斗和主菜单不需要这个方法。ready 也不等于允许交互：暂停、pending、未领取奖励、第四层等待等业务状态仍会限制操作。

## 正式入口与业务调用

直接运行工程主菜单，或打开 `ui/main_menu/menu_map_entry.tscn`。进入已有冒险不应调用 `SeedService.begin_run()`；正式新局由 `SaveGateway.start_new_run(seed_text, config) -> Error` 统一创建。已有局通过 `continue_saved_run() -> Error` 恢复；存盘用 `save_current() -> Error`，失败时保留当前页面并处理错误。`current_run()` 返回局状态，`map_checkpoint()` 返回地图检查点副本。

`EncounterFlow.bind_map(view) -> bool` 绑定 view 的 `map_run/session`。正式装配已经完成这个步骤。`begin_encounter(request) -> bool`、`open_battle()`、`capture_menu_checkpoint()` 和 `map_view_data()` 分别用于受校验的战斗入口、回到活动战斗、存档接缝和二维缩略图数据；战斗结算由它统一更新 Session、奖励和楼层。`waiting_for_fourth_floor()` 表示前三层完成但第四层未实现。

战斗 / 精英 / Boss、商店及随机事件已有唯一处理者。业务模块不能再次监听同一请求并重复发奖或结算。随机事件由 `RunRandomEvents` 和独立事件场景管理事务及恢复，正式入口将事件排除在模拟对话框之外；宝箱仍仅展示，不模拟领取奖励。以后接入宝箱系统时，要在 `menu_map_entry.gd` 同时替换 `_uses_demo_dialog()` 的分类与 `_on_world_node_requested()` 的路由，再连接恢复 / 结果回调。当前没有自动注册任意节点处理器的接口。

展示模块、音频、HUD 可监听已结算通知。跨场景切换时应重新取得当前地图实例，不能保存旧 view/session 作为权威对象。所有业务调用在主线程完成。

## MapEvents 全部信号

| 信号 | 参数 | 语义 |
| --- | --- | --- |
| `map_load_requested` | `snapshot: Dictionary, saved_state: Dictionary` | 请求当前装配加载，无同步返回值。正式换层由 Run/EncounterFlow 协调，不能只替换画面却绕过局状态。 |
| `map_loaded` | `map_id: String, seed: String` | 逻辑地图绑定完成，显示可能仍在准备。 |
| `player_cell_entered` | `map_id: String, coordinate: Vector2i` | 逻辑六边形坐标变化，可用于脚步 / HUD。 |
| `node_interaction_requested` | `request: Dictionary` | 新的节点业务请求。 |
| `node_interaction_restored` | `request: Dictionary` | 恢复已有 pending，重新绑定业务；不得当成新的奖励或遭遇。 |
| `node_result_submitted` | `result: Dictionary` | 向地图装配提交结果。 |
| `node_interaction_resolved` | `request_id: String, node_id: String, status: String` | 请求已被接受并结算，供后续表现监听。 |
| `map_state_changed` | `map_id: String, saved_state: Dictionary` | Session 状态副本，不是包含全部业务和随机流的存档。 |
| `boss_cleared` | `map_id: String, node_id: String` | Boss 完成通知；正式层数推进已有 EncounterFlow 负责。 |

信号声明在 `core/signals/map_events.gd`；Session 本身不发送这些信号，由装配 / EncounterFlow 发送。调用 `view.submit_node_result(result) -> bool` 可以同步知道接受与否；通过 signal 提交则监听 resolved，拒绝原因见 `session.last_error`。不要两种方式各提交一次。

## 节点请求、结果与地图数据

请求字段固定为：

```gdscript
{
    "request_id": "本次请求令牌", "map_id": "world:floor-001",
    "seed": "本局主种子", "floor_index": 1, "node_id": "node-01",
    "type": "event", "event_kind": "业务子类", "content_id": "内容ID",
    "is_route_gate": false, "visit_index": 0
}
```

`type` 是 `battle/elite/shop/boss/event/chest`；宝箱独立于随机事件，治疗等为 event 的子类。首次访问 visit_index=0，完成后递增。`request_id` 只用于当前请求的结果匹配，不能作为随机地址、长期节点 ID 或存档主键。

结果只要求两个字段：

```gdscript
MapEvents.node_result_submitted.emit({
    "request_id": active_request.request_id,
    "status": "completed" # 或 "cancelled" / "failed"
})
```

只有 completed 会记录完成、增加访问次数，并按关口规则重新计算探索。cancelled/failed 只清除 pending，不新增完成记录或访问次数；保留此前的 completed/visits（适用于已经完成节点的再次访问）。事件首次有效 request_node 即记录 opened，取消或失败不收回已揭示的身份；opened 不等于 completed，也不发奖励。地图忽略结果中的额外业务字段，不会根据 `gold/items/cards` 自动发奖；业务结果由对应系统持久化。没有 pending、旧令牌、重复令牌、非法 status 均拒绝。恢复 pending 后会生成新 request_id，异步业务必须使用恢复通知的新令牌。

| Session 方法 | 返回及约束 |
| --- | --- |
| `load_map(data: Dictionary) -> bool` | 候选校验后替换；失败保留原状态，原因在 last_error。 |
| `request_node(id: String) -> Dictionary` | 返回上述请求；已有 pending、不可见、过远、已完成且不能重访则 `{}`。 |
| `resolve_request(result: Dictionary) -> bool` | 低层纯状态结算，不发团队信号；正式模块优先走既有业务 / 装配路由。 |
| `nearby_nodes() -> Array[String]` | 当前可以交互的节点 ID。 |
| `reachable() -> Dictionary` | 逻辑连通地面集合，键 `"q,r"`、值 true；不受视觉高度影响。 |
| `can_stand(point: Vector2) -> bool` | 半径 1 单位平面上的脚部圆碰撞合法性，包含未知地形、关闭关口和已知节点的实体占地。 |
| `node_bodies() -> Array` | 当前已知、有效的占地副本；圆形 `{id,center:Vector2,radius:float}`，薄胶囊还带 `shape:"capsule",a:Vector2,b:Vector2`，坐标与尺寸均为逻辑平面单位。 |
| `move_actor(displacement: Vector2) -> Vector2` | 碰撞滑动后的最终 actor_plane；pending / 非有限输入不移动，单次位移限长 12；motion_path 用于沿真实路径插值。 |
| `collision_boundaries() -> Dictionary` | 当前已知可通行格的真实墙边副本，格式见下。 |
| `get_view() -> Dictionary` | UI 展示投影数据，必须按 known 过滤；不是存档。 |
| `get_snapshot() -> Dictionary` | 规范化平面快照深拷贝，可带 height_recipe；不含完整生成元数据，不能代替 Run 保存的楼层 snapshot。 |
| `capture_state() -> Dictionary` | 当前 Session 状态副本，格式见下。 |
| `restore_state(saved: Dictionary) -> bool` | 原子校验 / 替换；不恢复 SeedService。 |

坐标统一为轴坐标 `[q,r]` 或 Vector2i；连续位置 actor_plane 是半径 1 的逻辑平面 Vector2，不是屏幕像素，也不含显示高度。`Hex.to_plane(coord, 1.0)` / `Hex.from_plane(point, 1.0)` 做两者转换。脚部碰撞圆半径为 `0.18`，显示透视不能改变这个半径。

平面输入根字段为 `schema_version:1, map_id, seed, floor_index, spawn:[q,r], cells, nodes`，可选 height_recipe。cell 是 `{q,r,terrain}`，terrain 仅 ground/wall；node 是 `{id,type,coord,footprint,is_route_gate,revisitable,unlock_gates,event_kind,content_id}`。footprint 必须由唯一、未被其他节点占用的地面组成且包含中心。只有 battle/elite 可以是路线关口。输入坐标不可重复。可选 `body_radius` 为有限数字，范围 `0..0.45`；或使用互斥的 `body_capsule:{half_length,radius,axis:[x,y]}`，半长必须大于0、半厚不小于0，两者和不超过0.45，axis必须是有限单位向量。未声明时不新增实体碰撞，归一化不补写这些字段，以保持旧快照指纹。

`get_view()` 返回 `{cells,nodes,spawn}`。cell 添加 `known/gate_closed`；node 返回 `id,type,coord,known,completed,opened,event_kind,display_name,body_radius,body_capsule,is_route_gate`。event_kind 仅在事件 known 且 opened 时返回，未开启时为空、display_name 为“随机事件”；content_id、footprint 和高度不在视图协议内。全量格子可用于模糊轮廓，但未知节点的类型、图标不能直接呈现。

碰撞边界格式为 `"q,r" -> [{a:Vector2,b:Vector2,normal:Vector2,direction:int,neighbor_key:String}]`。a/b 是边线端点，normal 指向可走侧；显示层不可再按脚半径偏移这条边，否则墙根会与实际碰撞不一致。

Session 状态为 `state_version:1,map_id,fingerprint,actor_plane:[x,y],known:["q,r"],completed:[node_id],opened:[event_node_id],visits:{node_id:count},pending:{...}`。恢复要求版本 / map_id / 指纹匹配；known 必须等于关口状态推导结果，角色不可位于墙或未知地面；完成节点与前置关口、visits、pending 必须一致。opened 只能包含当前可见事件，不能重复；旧档缺失 opened 时从已完成 / pending 事件补齐，保留 state_version=1。不支持直接写 known 实现探索卷轴；该玩法需另加受校验的探索状态策略。

## 多层、生成器与存读档顺序

| 接口 | 规则 |
| --- | --- |
| `PlanarMapRun.new(source, content_version)` | source 实现 get_main_seed/get_stream/begin_run/capture_snapshot/restore_snapshot。 |
| `start_new_run(seed_text, configs, map_set_id="world") -> bool` | 显式新局，会调用 begin_run；正式菜单已完成新局时禁止重复调用。 |
| `attach_existing_run(configs, map_set_id="world") -> bool` | 接上已经初始化的 Seed；通用支持 1–20 层，目前正式配置三层。 |
| `enable_encounters(roster: Array) -> bool` | attach/restore 后、正式进入楼层前启用；已保存的怪物候选表属于该局。 |
| `monster_definition(id) -> Dictionary` | 获得该局已保存的怪物记录副本。 |
| `get_floor(index) -> Dictionary` | 首次生成后缓存；返回 `{snapshot,state}`，失败 `{}`＋last_error。 |
| `enter_floor(index, current_state={}) -> Dictionary` | 可存储当前状态并切换 current_floor；有 pending 时禁止离层。 |
| `store_current(state) -> bool` | 校验并保存当前楼层状态。 |
| `capture_snapshot(current_state={}) -> Dictionary` | 应传 session.capture_state()，否则可能捕获尚未同步的楼层状态。 |
| `restore_snapshot(saved) -> bool` | 校验全部楼层、配置、怪物与 Seed 后提交；失败不采用候选。 |
| `get_main_seed()/floor_count()/map_id_for(index)` | 查询主种子、楼层数与 `world:floor-001` 形式的稳定楼层 ID。 |

底层 `PlanarMapGenerator.generate(seed_source,map_id,floor_index,config={}) -> Dictionary` 要求 Seed 已初始化；成功返回包含生成版本、配置、格子和节点的楼层快照；height_recipe 为可选字段，switchback 路线配置会生成它；失败 `{}`＋last_error。`normalize_config(config)` 拒绝未知键。正式业务经 Run 调用并保存结果，不在每次进场重新 generate，否则会再次消耗生成随机流。

默认 `content_profile="legacy"` 支持 `size="small"`、normal 2–8、elite 1–5（战斗合计至少4）、events 4–16（包括商店和服务）。新增 `content_profile="alchemy_floor1"` 的固定配额见下一节；不能把其 elite=0 套用到 legacy。其余支持 `cell_space=1/3/4/7`、布尔 space_jitter、layout_candidates 1–4、layout_profile legacy/compact、route_profile legacy/switchback。min_boss_content_nodes、transition_count、transition_steps、obstacle_rate 也由 normalize_config 校验；范围以生成器为准，不能随意增加未支持键。

整局地图快照为 `run_version:1,generator_version,map_set_id,current_floor,floor_configs,seed_snapshot,floors:[{floor_index,snapshot,state}],generation_failures:[{floor_index,error}]`，正式怪物启用后另有 encounter_roster。这个快照仍不替代角色牌组、商店库存等全局业务存档。

正式恢复顺序：SaveGateway/GlobalState 恢复真实 Seed 与业务 → 地图通过 ExistingSeedSource 验证同一 Seed 快照并恢复 PlanarMapRun → 取当前楼层 → `load_map(snapshot,state)` → EncounterFlow 绑定业务 → 恢复战斗 / 商店 / 奖励。ExistingSeedSource.restore_snapshot 只比较，不重装 registry；重复 begin/restore 会令业务持有的旧 RandomStream 失效。

统一存盘通过 `SaveGateway.save_current()`；磁盘扩展为 `menu_map_checkpoint:{run_id,snapshot}`。Seed 要求协议、精确 Godot build、content_version 匹配，不能承诺跨引擎升级重现。旧局沿用其保存的几何和配置，新局才使用当前三格扩展。

## 高度与展示适配协议

以下供地图维护者使用，战斗 / 事件无需直接访问 renderer。

| 接口 | 输入、输出与失败行为 |
| --- | --- |
| `HeightGenerator.normalize_config(config)` | 校验公共 / 逐层合并后的高度配置，未知键与非法范围返回 `{}`＋last_error。 |
| `HeightGenerator.generate(planar, noise_seed:int, config={})` | 纯显示计算，不改输入通行图；noise_seed 为有符号32位，最多4096格；失败 `{}`。成功增加整数 cell.level、墙冠、height_quantum、outer_radius、节点基础及 metadata.height。 |
| `SupportSampler.load_layer(layer) -> bool` | 校验量子、半径、相邻地面差≤1级、基础同高；失败保留旧采样场。 |
| `set_visibility(known, restricted=true)` | 按已知地面构造脚底高度插值；探索收缩时重建。 |
| `height_at(plane) -> float` / `level_height(coord) -> float` | 连续脚底显示高度 / 名义格高；缺少数据返回0，不代表可通行。 |
| `MapPresentation.acquire(borrower,run_identity) -> Node2D` | 取得唯一 renderer，隐藏并恢复处理；局身份变化清旧缓存。 |
| `owns(borrower) -> bool` / `present(borrower)` / `release(borrower)` | 校验借用者；release 只隐藏并禁用处理，保留当前层缓存。 |
| `clear()` | 销毁 renderer 并清理线程 / 缓存；不会保存任何业务状态。 |
| `view.load_map(snapshot,state={}) -> bool` / `capture_state()` | 公共装配入口；载入接受不代表显示已就绪。 |
| `view.is_map_ready() -> bool` | 高度、几何与显示状态预计算完成；非战斗许可判断。 |

renderer 的 `set_layer(snapshot,known,completed,synchronous_binding=false)`、`project_plane(point,height=0)` / `unproject_plane(screen,height=0)`、`set_wall_cutaway_context(map_id,seed,floor,reachable,defer_refresh=false,collision_edges={})` 由适配层统一调用。投影坐标为 renderer 的局部显示坐标，外部屏幕位置必须先应用 Camera2D/Viewport 变换。`pick_cell(local_screen)` 只作显示拾取，是否能到达仍由 Session 判断。

显示提交信号为 `presentation_committed`；异步操作使用 `is_rebuilding()`、`is_presentation_cache_preparing()` 与 `get_presentation_cache_progress()` 查询，正式场景已包装为 is_map_ready。光影入口为 `set_sun_config(config,rebuild=true)`、`set_atmosphere_config(config,rebuild=true)`，角色更新为 `update_actor(plane,height)`，动态统一刷新为 `flush_dynamic()`。修改光影配置可能使缓存失效，不能在每帧当动画调用。

`_known/_source_snapshot/_cache_view`、线程、材质与批次都是内部实现，不是稳定业务接口。显示层新增随机地址会出现在 Seed 快照中，但注册不抽样，不替换共享 registry。

## 配置与随机地址

- `data/config/relief_2d/exploration.json`：三个楼层的节点配额、紧凑轮廓、折返路线、`cell_space: 3`，以及公共 / 逐层高度策略。新局采用这一配置；已有局使用自己的保存配置。
- 固定投影 35.264°，原格半径 1，高度量子 `quantum: 0.2`（此前原步高的 1/3）。沿用 `regional_articulated`，第二层 Boss 在低处、第三层在最高处的规则。
- 默认移速 200%、地图缩放 650%；角色 100%。滚轮范围仍为 50%–1600%。
- `actor.json`、`sunlight.json`、`atmosphere.json`、`rock_scatter.json` 分别管理动画、太阳光、暖暗氛围 / 雾、石堆与小石子。不要把显示配置写入通行判断。
- 高度随机地址为 `map.height / [map_id, "relief-height-v1"] / 0`，外围为 `map.scenery / [map_id, "context-envelope-v3"] / 0`。装配通过公开 snapshot 读取派生 seed，不消耗该流的抽样次数，也不恢复 / 替换共享 registry。
- 保留当前工程 `seed_content_version = jam-map-seed-v1`。不使用旧独立预览的内容版本覆盖正式存档。

`Session.get_view()` 返回全量格子和节点，并标记 `known`；每个展示调用方都必须过滤未知节点。本适配层的节点显示只使用当前已知节点；墙体透视仍受 session 可达域约束，视场雾与探索遮蔽是两层不同职责。缩略地图继续使用二维逻辑坐标。

## 场景生命周期与存档

`MapPresentation.acquire(view, run_id)` 为当前地图提供唯一 renderer，退出通过 `release(view)` 隐藏并禁用处理。释放、显示提交回调和延迟 discovery 准备均检查当前借用者，阻止已离场实例继续发布显示结果。雾节点只创建一次；换层清理旧层显示缓存，新局清理上一局。

战斗期间保留一层显示缓存，以减少战后回图等待；这是有界的内存换时间策略。加载同 run_id 的更早存档时，按保存的 known/completed 恢复显示，不能沿用更晚的揭雾权限。真正的存档只经 `SaveGateway`、`PlanarMapRun` 和 `PlanarMapSession`。

旧平面存档不重新生成、不移动节点、不改原路线；加载后可在原几何上增加高度显示。未生成的旧楼层仍使用该局保存的旧生成配置。需要体验三格扩展，应创建新局，不能静默替换玩家正在进行的地图。

正式流程仍是前三层 Boss 推进，第三层结束提示“第四层暂未开放”；未新增第四层地图。同步 2026-10-19 整合版后，随机事件接入正式 RunRandomEvents 场景、选择和存档事务；宝箱仍仅展示，等待业务接入，不虚构奖励。

### 节点实体与可读性（2026-10-19）

新生成的第一层普通战斗 / 宝箱声明 `body_radius:0.34`，Boss 为0.42，商店为0.38。随机事件改用 `body_capsule`：半长0.32、半厚0.012、轴向 `[cos(35°),-sin(35°)]`，总宽0.664、厚0.024，相当于沿固定镜头横向竖起的薄片。这里的单位仍是原六边形外接半径=1；所有实体外接半径上限0.45，角色脚圆仍为0.18。显示高度和缩放不改变尺寸，参数集中在 `flat_2d/node_geometry.gd`。

碰撞沿用 Session 的移动、连续扫掠和贴边滑动流程。只有已知节点产生实体，不会用未知障碍提前泄露节点位置；关闭关口沿用完整 footprint 阻挡，完成关口才释放。普通战斗、Boss、宝箱完成后释放占地；商店和事件保留。请求取消、失败不释放。存档恢复校验角色不能进入有效实体内部。旧存档未声明碰撞时保持原状，已声明圆形的旧事件也不自动改形状，保持快照指纹和存档位置兼容；体验薄片碰撞请新建局。`node_bodies()` 的圆形仍返回 `{id,center,radius}`；胶囊另返回 `shape:"capsule",a,b`，端点均为逻辑平面坐标。`get_view()` 仅对已知有效实体返回描述，未知或已释放胶囊返回空字典。

实体贴图的最低点对齐碰撞体朝镜头一侧的前沿，圆形前移radius、事件薄片前移0.012，避免将贴图放在碰撞体中心造成前方空白卡人。非事件的轻微接触阴影仍按逻辑圆投影；随机事件没有投影或圆形接触阴影，只保留与薄片宽度一致的窄底边。文字按实际字形墨迹下沿对齐底边，并在窄幅内换行，不采用含字体留白的行框底部。当前事件绘制适配固定35°水平偏转的横轴；若未来自定义其他胶囊轴向，需要同时提供对应朝向的节点绘制适配。角色移动阴影只落在实际地形表面，并在接收地形原有绘制顺序内更新，不再盖到节点 PNG 或其透明区域。节点绘制批次不使用依赖地形自定义顶点格式的墙面材质，仍使用场景预计算色调和探索雾。 角色与节点之间按实际脚点深度排序，仅 PNG 的不透明轮廓裁剪角色；透明空白、文字占位、接触圈和已淡出的完成图标不会整块挡人。轮廓在主线程首次载图时按最长边64像素缓存为合并矩形，移动只查询相交片段；这是有界精度近似，不是将图像矩形当作实心墙。

当**已知、未完成、当前可交互且被选中**的战斗关口被墙或雾边挡住时，显示小型贴图 + E 提示，引线指向入口。提示使用 `Session.get_view()` 和 `nearby_nodes()`，离开范围、暂停、进入交互、完成或换层即撤下。提示不会扩大迷雾授权区域，也不显示未知节点或未开启事件身份。其他节点继续按正常场景顺序显示。


### 原生战斗调试按钮

预览工程显式设置 `debug/map_battle/enable_instant_victory=true` 后，正式战斗界面显示“调试：立即胜利”。仓库产品配置默认不开启，release 预览也必须单独开启；此开关不写入存档。

按钮只接受当前 Run/EncounterFlow 绑定、处于玩家行动阶段且事件队列空闲的战斗；开局、动画、选择或结算过程中禁用。它调用 `BattleStateMachine.debug_finish_victory()`，只在显式开关启用时将敌人标记为击败并进入原有单次胜利结算，不触发伤害、反伤、变身或召唤等战斗反应。仍经正常奖励、保存、返回地图流程完成节点，不直接修改地图 completed/pending，也不模拟击杀触发的额外效果。重复点击和已结束战斗不重复发奖励；领奖完成后回图，关口 footprint 与战斗实体均按原完成规则释放。关闭战斗界面仍保留未完成战斗，败北处理保持原状。

### 差分与素材更新合同

| 素材变更 | 必须同步的内容 |
| --- | --- |
| 图集重排 / 尺寸变化 | `env005-atlas.png`、manifest.size、各 layer 的 `atlas:[x,y,w,h]`，矩形必须在图集内。 |
| 增加地表差分 | 稳定 layer.name；pools.ground 中稳定 id、weight 与 `regions.top` 引用。 |
| 增加墙面差分 | 一个 pools.wall 条目包含 wall1/2/3 三方向对应 layer；不是把三方向当三种随机墙面。 |
| 增加地面装饰 | pools.decoration 条目提供 id、region、weight、width；decoration_probability 控制出现率。 |
| 石堆 / 石子 | 当前直接引用 `rubble-1..2` / `pebble-1..3`，由 rock_scatter.json 管理，不属于上述三个 pool。 |
| 改变裁切 / 轮廓 | 同步 crop、atlas 和 normalized outline；outline 坐标0–1。file/source/sha256 用于来源追踪，运行时不做 SHA 校验。 |
| 替换角色 | 同步 actor.json 的 frame_size、foot_anchor、frame.path/region、alpha_union_bbox/max_body_height_px，并重新烘焙 body_cutaway_mask。 |

变体 ID 必须稳定且在池内唯一，weight 有限非负，0 表示停用。池按 ID 排序，以坐标和稳定地址选择差分，不消耗玩法随机流；改变权重或增删选项会改变外观，不保证相同 seed 仍选同一张素材。`manifest.json` / `source_recipe.json` 不是运行中热更新协议，修改素材后重启验收。

大石堆20%指符合条件的贴墙候选格概率，后续支撑、间距、节点保护检查可能拒绝，不保证全图20%铺满。小石子使用疏密斑块和最小间距，同格可多个；它们是装饰，不新增碰撞。当前石子宽度范围为0.20–0.36个原格半径。
