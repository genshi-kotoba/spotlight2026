# 典籍残片系统（PRG-009）

入口：冒险菜单的背包页。战斗内典籍为只读展示。
原独立编辑场景 `ui/relics/relic_test_scene.tscn` 已移除，编辑改在背包页完成。

棋盘为 **4 列 × 3 行**，每格保存一个残片 ID 或空字符串。
残片数量、掉落、购买与鉴定尚未引入。

## 编辑与展示

1. 编辑在背包页完成：放置、拖动、交换与移除残片。
2. 战斗左侧展示 12 格构筑、生效次数和最近四条效果记录；生效格会闪亮。
3. 测试场景左侧的“重开测试”可用已保存的典籍布局开始新一局；敌人默认 3000 血，避免强构筑在首抽时就终结战斗。

当前项目地图主入口保持原配置；单独运行战斗场景按 F6 即可，典籍为只读展示。

## 五种测试残片

| ID | 类型 | 名称 | 行为 |
| --- | --- | --- | --- |
| `on_card_gained` | 触发 | 拾页 | 获得卡牌时，激活周围四格的效果残片 |
| `on_enemy_damaged` | 触发 | 余震 | 对敌人造成伤害时，激活周围八格的效果残片 |
| `deal_damage` | 效果 | 灼刻 | 造成 2 点基础伤害 |
| `gain_block` | 效果 | 护纹 | 玩家获得 1 点格挡 |
| `turn_strength` | 存在 | 恒力 | 每个玩家回合开始、抽牌前获得 1 层力量 |

定义与数值：`data/relics/test_fragments.csv`，通过 `RelicCatalog` 读取为
`RelicFragmentData`。CSV 的导入设置为 Keep File，作为游戏数据而非翻译文件。
导出游戏时需在导出预设的非资源包含过滤器中包含 `*.csv`。

## 已落实的规则

- 四格：上、下、左、右（曼哈顿距离等于 1）；八格：加四个对角（切比雪夫距离等于 1）。
  范围不包含触发格自身，也不会跨行、环绕或越过页面边界。
- 触发残片只激活范围内的**效果类**，不直接激活触发类和存在类。
- 存在类只需放在页面任意位置，无需相邻触发条件；效果类独立放置不会自行生效。
- 本轮“获得卡牌”指卡牌**进入手牌**，包含首抽、每回合抽牌和卡牌效果抽牌。
  洗牌、点击选择出牌、取消编排不算获得。以后新增卡牌到手牌等操作，可调用
  `RelicBattleSystem.notify_event("card_gained")` 接入。
- 敌人受到正数、未完全被格挡的伤害会触发余震；玩家自伤、零伤害不触发。
  当前也包含对敌人的中毒伤害和残片伤害。
- 灼刻复用 `BattleEffectContext.damage_enemy()`：力量/虚弱影响其基础 2 点伤害，
  伤害下限为 0，格挡正常抵挡。拾页触发的伤害优先选择首个存活敌人；余震优先攻击
  本次受伤的存活敌人，若其已死亡则选择首个存活敌人；没有存活敌人则跳过伤害。
- 格挡沿用既有规则，在敌方回合结束清零。力量本回合结束清除，下一玩家回合重新
  获得 1 层，不会因为存在类持续生效而无条件跨回合累积。
- 残片全程监听战斗事件，在首回合抽牌前完成接入，战斗结束后停止触发。
  抽牌触发残片伤害致死时，停止继续抽牌并立即判定战斗胜利。

## 连锁顺序与循环保护

同一个事件的触发残片按页面从上到下、从左到右遍历，各触发残片覆盖的效果也按
同样顺序加入战斗统一事件队列。普通事件保持 FIFO；当前事件产生的子反应按发出
顺序优先处理，在下一效果、下一张牌或下一阶段之前完成。典籍不再维护独立的同步
结算循环，使用同一规则引擎注册触发条件和效果。详见 `09-战斗事件队列与规则引擎.md`。

每个任务保存自己的触发来源路径：同一个触发格在**同一条因果路径**里只允许进入
一次，其他触发格仍可继续连锁。下一次独立抽牌/伤害重新建立路径，因此仍可再次
触发；两条独立来源也都可以激活同一个效果格。

例如两个余震围绕一个灼刻，外部伤害会分别激活 A、B，再允许 A→B 和 B→A，
但阻止 A→B→A 和 B→A→B。因此灼刻可以执行四次而不是无限循环。
单条根事件最多结算 128 个典籍效果，同时待处理的典籍任务最多 128 项；达到
执行上限后跳过该根的剩余典籍效果并发出 `chain_limited`，HUD 提示达到安全上限。
不会清空同一队列中的正常卡牌或回合续接。另有 256 次指针结算保护与单次队列推进
50000 个事件的兜底预算。下一玩家回合清理典籍预算追踪字典。

## 保存与接入

配置文件：`user://relic_test_board.json`，与已有全局存档独立。

```json
{
  "version": 1,
  "columns": 4,
  "rows": 3,
  "cells": ["turn_strength", "on_card_gained", "gain_block", "", "", "deal_damage", "on_enemy_damaged", "", "", "", "", ""]
}
```

保存先写临时文件再替换，失败时不跳转场景；加载校验版本、尺寸、数组长度和
残片 ID。不存在文件时背包页载入示例、单独启动的战斗使用空配置；无效存档由
背包页提示错误并允许重新编排，战斗初始化则明确失败。

战斗运行系统复制布局，当前战斗的构筑不会被编辑对象后续变化影响。编辑在背包页保存后生效。

`systems/relics/` 只包含定义、布局和事件逻辑；背包页负责编辑与拖放；
战斗场景负责装配 `RelicBattleSystem` 与现有 `BattleStateMachine`、效果适配层。
新增的 `player_turn_started` 信号位于抽牌之前；已有 `turn_started` 仍在行动阶段
发出，保持原来的每回合 UI 抽牌接口。
