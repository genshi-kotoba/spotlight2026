# 场景切换与存档开销

本次调整战斗／事件进出时的重复工作，不改变地图、节点、迷雾、光影、奖励、存档格式或随机流地址。统一转场仍使用 `SceneTransition`；场景准备完成后才能恢复操作，不能提前解除遮罩来缩短统计时间。

## 地图进入与返回

`map_demo.gd` 增加 `_initial_state() -> Dictionary`，默认返回空字典。基类 `_ready()` 将 `_initial_snapshot()` 和 `_initial_state()` 一起交给第一次 `load_map(snapshot, state)`。

正式入口 `menu_map_entry.gd` 在 `_initial_snapshot()` 中完成原有存档／地图运行状态恢复，再由 `_initial_state()` 返回 `_saved_entry_state`。因此返回地图时直接绑定真实位置、已探索区域和节点状态，避免先绑定出生状态、随后再加载一次已保存状态。

新增地图入口需要恢复状态时应覆盖此方法，不要在 `super._ready()` 后再次加载同一地图。真正的换层仍按原流程加载新层；纯 2D 默认入口无需高度参数。

同层返回继续复用 `MapPresentation` 的纯显示缓存。缓存身份、各揭雾状态的预备和就绪检查均保留；没有把预备工作延期到移动或战斗揭雾时。

## 保存接口

团队仍调用 `SaveGateway.save_current() -> Error`，并在返回 `OK` 后继续确认节点或离开场景。不要绕过该入口直接写文件，也不要改成不等待结果的后台保存。

状态机新增内部辅助接口：

```gdscript
var prepared: Dictionary = global_state.build_save_payload()
# {"error": Error, "payload": Dictionary}
```

它构建原有完整载荷，并在构建活动局时捕获种子快照；不写文件、不切换保存路径、不发送保存失败信号。原有 `RunStateMachine.to_dictionary()` 的规范化行为仍存在。调用者必须检查 `error`，不能把空载荷当成有效存档。

`SaveGateway` 取得载荷后附加原有地图检查点，直接执行一次既有原子安装，省去 `.menu-staging` 的写入、读回、JSON 解析和重复序列化。队列空闲检查、地图检查点、种子捕获、未点击继续时的活动局、备份恢复和最终写入失败处理均保留。只有最终安装成功，才更新内存检查点并通知档位变化。

独立调用状态机的 `save_game()` 仍可用；它也通过同一载荷构建方法调用自己的原子写入。玩法调用不需要使用这个内部方法。

## 事件返回

普通事件的结果页提供“返回地图”按钮，控件名为 `EventReturnNow`。原有约两秒的结果阅读后自动返回保留；玩家可立即返回。

按钮和自动计时器可能在同一帧到达，`_finish()` 只受理仍处于 `result` 的事件，并先更新 generation 使旧计时器失效。奖励、结果保存和确认事务仍走 `RunRandomEvents`，不重复领取或重复离开。赌博事件原有“继续抽取／结束”操作保留。

## 生成计算

- 平面生成的局部 BFS 使用预先按坐标排序的六个方向，替代每次构造字典和排序邻居；遍历顺序与旧实现一致，不改变布局或 RNG 消耗。
- 高度局部修整只需至多三格的峰谷。专用扫描保持原有坐标／邻接／FIFO 顺序、出生点字段和保护格规则，避免构建随后被丢弃的大分量诊断记录。它用于当前受约束的高度生成域，不是任意 int64 高度输入的公共工具。

上述两处均保持完整输出一致，因此不增加地图／高度算法版本，不使旧存档失效。

## 验证口径

端到端耗时从真实按键或按钮输入投递前开始，直到目标场景首个已绘制且能操作的帧；另列开局结算、领奖回图和首次换层。普通事件的自动返回包含阅读时间，不能把按钮跳过阅读称作资源加载提速。

本轮外部验证覆盖完整战斗／领奖／回图、关口揭雾、事件事务、独立读档、保存失败保留旧文件、防重复领取、种子快照和生成结果一致性。验证代码、采样数据和原生预览包不属于产品源码。首次新层的地形与全部揭雾状态预备仍是较重的路径，不能用同层返回的毫秒数据代表换层速度。
