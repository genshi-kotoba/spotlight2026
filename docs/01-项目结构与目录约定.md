# 项目结构与目录约定

本文规定 `res://` 下的代码组织方式。新增文件之前先在这里找到它该去的位置，找不到就说明结构需要补，而不是随手放一个。

## 目录布局

```
res://
├── core/                 与业务无关的地基
│   ├── signals/          全局信号总线，模块间唯一的解耦通道
│   ├── constants/        枚举、常量、配置键名
│   └── utils/            纯函数工具，无副作用、不依赖节点
│
├── autoload/             全局单例脚本，由 project.godot 挂载
│
├── state_machines/       三套状态机，游戏骨架
│   ├── global/           PRG-002 局外存档、成就、设置
│   ├── run/              PRG-003 单局的地图、玩家、牌组、道具
│   └── battle/           PRG-004 回合流程、结算、怪物行动
│
├── systems/              功能系统，纯逻辑，不含界面
│   ├── random/           PRG-005 随机种子与生成器
│   ├── cards/            PRG-007 / PRG-013 卡牌定义与效果模板
│   ├── buffs/            PRG-008 buff 效果模板
│   ├── relics/           PRG-009 典籍残片，拼接与条件/效果组件
│   ├── potions/          PRG-010 药剂
│   ├── map/              PRG-011 地图生成
│   ├── events/           PRG-012 随机事件
│   ├── text/             PRG-014 文本载入
│   └── audio/            PRG-015 音频
│
├── ui/                   界面层，每个界面一个目录，场景与脚本同住
│   ├── main_menu/        PRG-016 开始界面
│   ├── battle/           PRG-017 战斗界面
│   ├── world_map/        PRG-018 地图界面
│   ├── deck/             PRG-019 牌组界面
│   ├── achievements/     PRG-020 成就系统及界面
│   └── settings/         PRG-021 设置
│
├── data/                 数据与配置，禁止硬编码进代码
│   ├── cards/            卡牌 csv
│   ├── relics/           典籍残片 csv
│   ├── texts/            对话与事件 txt
│   └── config/           .tres 配置资源
│
├── assets/               美术与音频，按资产表编号命名
│   ├── ui/               UI-0xx
│   ├── env/              ENV-0xx
│   ├── chr/              CHR-0xx
│   └── audio/
│
└── tests/                自测脚本
```

## 文件放哪里

| 内容 | 位置 |
| --- | --- |
| 与业务无关的工具函数 | `core/utils/` |
| 模块之间的通信 | `core/signals/` 的信号总线，不要相互直接引用 |
| 纯逻辑，无场景无界面 | `systems/` |
| 有节点树、有界面 | `ui/<界面名>/` |
| 一个玩法实体的定义与行为 | 对应的 `systems/` 目录，一个文件一个职责 |
| 数值、文案、配置 | `data/`，代码里只留读取逻辑 |

## 命名

| 类型 | 规范 | 示例 |
| --- | --- | --- |
| 脚本文件 | `snake_case.gd` | `card_effect_draw.gd` |
| 类名 | `PascalCase` | `CardEffectDraw` |
| 场景文件 | `snake_case.tscn` | `battle_hud.tscn` |
| 常量 | `UPPER_SNAKE` | `MAX_HAND_SIZE` |
| 信号 | 过去式，描述已经发生的事 | `card_played`、`turn_ended` |
| 私有成员 | 前导下划线 | `_internal_counter` |

## 依赖方向

依赖是单向的，反向依赖一律视为设计错误，先改设计再写代码。

```
ui  →  systems  →  state_machines  →  core
                                        ↑
                                      data（只读配置）
```

具体讲：

- `core/` 不依赖任何其他层
- `systems/` 不认识 `ui/`，只发信号，谁听谁处理
- `ui/` 不直接改 `state_machines/` 的内部变量，调公共方法，听信号更新

## 拆分的例子

以抽牌为例。反面写法是把逻辑塞进 `battle.gd` 的一个函数里，正面写法是：

```
systems/cards/effects/
├── card_effect_base.gd      抽象基类，定义接口与信号
├── card_effect_draw.gd      只负责抽 N 张
└── card_effect_damage.gd    只负责造成 N 点伤害
```

调用方只认基类接口。以后加新效果，不需要动已有文件。
