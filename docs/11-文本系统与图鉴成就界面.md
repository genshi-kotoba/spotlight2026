# 文本系统、图鉴与成就界面

本次实现 PRG-014 的展示文本读取及 PRG-020 的成就展示/进度接口，按新增需求扩展主菜单图鉴。CSV 是展示属性来源，JSON 档案保存解锁/完成状态，既有事件队列、规则引擎和卡牌效果资源不变。

## 入口与操作

F5 打开开始界面，点击“图鉴”默认进入卡牌图鉴。“卡牌 / 典籍残片 / 怪物”按钮切换类别；右侧显示模式按钮循环切换“显示所有 → 显示已解锁 → 显示未解锁”。切换类别保留显示模式，列表始终按编号自然排序（2 在 10 前）。未解锁条目仍可在所有/未解锁模式查看完整详情，不擅自添加遮罩隐藏信息规则。

网格编号显示在卡片外。卡牌、残片卡面只显示卡名和效果文本，图片由资源路径载入。点击条目打开详情：左侧预览，右侧显示所有 CSV 属性和存档中的解锁状态。右侧长文本可滚动；“关闭详情”或 Esc 关闭。

开始界面“成就”打开成就列表，按编号排序。每条仅显示成就名、要求文本、奖励，不显示编号/内部完成字段，不提供详情按钮。绿色背景表示已完成，其他为未完成。两页均可返回开始界面，不创建/结束对局。

## 四份空 CSV

正式文件只有表头，无测试记录。空表显示明确空态；要看到正式内容，在表头下添加数据，重新运行游戏即可。开发时也可调用 `TextCatalog.reload()` 重读并刷新界面。

| 文件 | 固定列名与顺序 |
| --- | --- |
| `data/text/cards.csv` | 编号、卡图资源路径、卡名、效果文本、类型、文本 |
| `data/text/fragments.csv` | 编号、卡图资源路径、卡名、效果文本、类型、文本 |
| `data/text/monsters.csv` | 编号、怪物图资源路径、怪物名、能力文本、类型与出现地、文本 |
| `data/text/achievements.csv` | 编号、成就名、要求文本、奖励 |

残片按用户“其余与卡牌皆相同”的要求使用同样六列，但完全独立的文件。解锁状态、完成状态**不加入 CSV**，避免重读文本重置进度。

- 编码为 UTF-8（可带 BOM），使用半角逗号分隔。Excel 请另存为“CSV UTF-8”。
- 表头必须与上表一致。编号不可为空，同一表不可重复；其他属性允许留空。编号始终按字符串处理，前导零不被游戏丢弃，建议编辑器将该列设为文本。
- 含逗号/换行/双引号的文本使用 CSV 双引号包裹，内部双引号写作两个双引号。支持 CRLF、LF 与跨行文本。
- 整行空白忽略；错误表头、重复/空编号、列数不符、引号错误会拒绝整张表，页面显示错误，不展示半份记录。
- 图片路径填写项目内 `res://...png` 等路径，支持 png/jpg/jpeg/webp/svg。缺失或不支持的路径不会崩溃；卡牌/残片保留现有卡框，怪物显示图片空态。
- “类型与出现地”目前按用户要求是一列自由文本，可以填写“精英 / 第二地区”。
- `.csv.import` 使用 `keep` 导入器，避免被 Godot 当作翻译表；原始文本会作为资源保留。若新增独立 TXT，在导出预设的非资源包含筛选中加入 `*.txt`。

卡牌编号应与已有 `CardData.card_id` / `GlobalState.unlocked_cards` 完全一致，才能共享运行卡牌与图鉴的状态与展示。`CardView` 在游戏运行时优先使用匹配编号的 CSV 卡名、效果文本和图片；不存在对应记录时，原有测试卡 `.tres` 文案保留。编辑器 @tool 预览仍按 `.tres`，CSV 不清空或改写规则资源。

已有测试残片的行为文件 `data/relics/test_fragments.csv` 不变。本次 `data/text/fragments.csv` 只提供图鉴展示属性，不替代触发事件、范围和效果参数。正式内容未填前，图鉴不会自动捏造/复制测试卡和测试残片记录。

## 读取与状态接口

autoload `TextCatalog`（`systems/text/text_catalog.gd`）统一服务：

```gdscript
var cards := TextCatalog.entries("cards", TextCatalogService.DisplayMode.ALL)
var record := TextCatalog.entry("cards", "CARD-001")
var unlocked := TextCatalog.is_unlocked("cards", "CARD-001")

# 明确的游戏规则在确认获得/解锁后调用；返回 Error，调用方必须处理保存失败。
var error := TextCatalog.unlock_entry("cards", "CARD-001")
error = TextCatalog.unlock_entry("fragments", "FRG-001")
error = TextCatalog.unlock_entry("monsters", "CHR-025")
error = TextCatalog.complete_achievement("ACH-001", {"source": "battle"})
```

状态接口只接受相应 CSV 已存在的编号，成功修改后通过 `SaveGateway.save_current()` 保存当前档案。底层 `GlobalState.unlock_card()`、`unlock_collection()`、`complete_achievement()` 仍供规则代码使用，直接调用底层时须自行保存。重复解锁/完成不会产生重复进度或覆盖首次完成时间。保存失败返回错误并保留内存进度，可再次保存；不能将失败返回视作已经落盘。

`catalog_changed` 在重读后通知；`progress_changed` 在档案装载、解锁/完成后通知。图鉴筛选与详情订阅更新，成就背景同步更新。

存档保持 v1，新增顶层可选 `unlocked_fragments`、`unlocked_monsters` 字符串数组；缺少字段的旧存档按空数组读取。卡牌继续使用 `unlocked_cards`，成就继续使用 `achievements`。三档独立保存，切换空档不会继承上一档进度。删除 CSV 记录只影响展示，不删除档案中的旧编号状态。

成就“要求文本”和“奖励”目前是纯展示文本，**不是机器可执行条件**。未定义正式条件/奖励配置前，不解析自然语言、不自动发奖励。后续规则可监听 `GlobalState.achievement_check_requested` 或战斗事实事件，判定后调用完成接口；奖励执行应接入正式规则并保证幂等。

## TXT 与文本参数

PRG-014 的事件/对话 TXT 通过同一服务读取。建议后续放在 `data/text/dialogues/`、`data/text/events/`，本次不编造正式剧情。

```gdscript
var result := TextCatalog.read_text("res://data/text/events/example.txt", {"name": "玩家"})
if result.error == OK:
    label.text = result.text
var effect := TextCatalogService.format_text("造成 {damage} 点伤害", {"damage": 2})
```

只允许项目内 TXT，拒绝 `user://`、父目录逃逸等路径。`{参数名}` 一次替换，未知参数原样保留，参数值不递归展开；作为 Label 纯文本显示，不执行 GDScript 或 BBCode。CSV 的效果文本不替代战斗规则和效果参数。

## 结构与验证

- `systems/text/csv_text_table.gd`：严格 CSV 解析、验证、自然排序。
- `systems/text/text_catalog.gd`：四类目录、筛选、文本格式化、状态/保存接口。
- `ui/catalog/catalog_ui.gd`：公共页面样式、卡面复用、图片安全载入。
- `ui/catalog/encyclopedia.gd/.tscn`：三类图鉴与详情。
- `ui/catalog/achievements.gd/.tscn`：三字段成就列表。
- `tests/text_catalog_selftest.gd/.tscn`：CSV 异常/跨行、排序、筛选、卡面与详情、菜单入口、解锁/成就保存、旧存档兼容与三档隔离；图形模式生成验证截图。

测试夹具只写唯一 `.godot/text-catalog-*` 目录，正式 CSV 仍为空，不改玩家档案。CSV 模板另经过 spreadsheets 技能的字段/空表验证。
