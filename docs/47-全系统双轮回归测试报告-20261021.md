# 全系统双轮低并发回归测试报告

测试日期：2026-10-21。对象为当前桌面 `spotlight2026-main` 与独立 `android` 工程。

正式运行区间：00:58—01:58。两端两轮共 252 项次（64 个不同入口／变体，含 8 次限时启动检查；另 2 次夹具准备不计入）。196 项次退出为 0、54 项次非零退出、2 项次超时。退出为 0 的结果中，另有 4 项次含脚本异常、4 项次含音频测试页 API 错误；不等同于 196 项次无错误通过。

## 结论与判读方式

两轮均执行完整清单，不仅重跑失败项目。结果中存在未通过、测试夹具失效、运行脚本异常和不稳定的原生鼠标交互，不能将本版本判定为“全系统无问题”。具体执行数量与逐项结果见后文。

54 次非零退出中，48 次来自 12 组旧规则断言、失效夹具或独立工具加载入口，另 6 次来自 4 组原生悬停／后排命中检查。它们不是 54 个独立游戏 Bug。桌面资源包自测另有 2 次限时终止；未观察到 Godot 引擎进程崩溃。

`PASS` 是该进程的退出码为 0；仍需检查脚本异常及音频错误。后文专门列出“退出成功但有脚本异常”，不能将其视为干净通过。负向用例主动制造的非法配置、损坏快照、保存失败和队列预算错误，不直接等于游戏缺陷。

## 执行方法与范围

- 始终串行，只运行一个 Godot 测试实例；不做长时间压力或大规模随机轰炸。
- Godot 4.7.2，Windows OpenGL Compatibility 实际渲染场景测试；独立 SceneTree 脚本使用 headless。仅按帧计数的三个手牌／发牌用例启用 fixed-fps 60，其余使用真实时钟并限帧 60，避免顿帧测试的时钟假阳性。
- 两端各自建立临时工程配置，资源及脚本指向各端原文件，保留各自平台配置与 UI。临时 `user://` 独立于正式档案，存档恢复测试使用生成的隔离档案及其副本，没有覆盖正式进度。
- 自动覆盖：状态机、事件队列和规则引擎、正式卡牌／Buff／附魔、手牌输入与动画、怪物目录／多动／意图／召唤、漂浮文本、分层背景、地图种子与交互、四层流程、随机事件、背包与奖励选包、商店及删牌驱魔、万灵药升级、典籍解锁、图鉴文本、设置、存读档／覆盖回滚、死亡／胜利及记录、预加载／场景切换，以及 Android 触屏输入与地图二次点击交互。
- 开始场景和交互音频测试页另外做限时启动检查。这类检查只证明可启动，不等于全部按钮、全部音频均已人工验收。
- 脚本／业务数据双端对照：检查 `tests`、`state_machines`、`systems`、`data`、`autoload`，仅 `systems/map/relief_2d/node_interaction_hint.gd` 存在端侧差异。没有将桌面 UI 覆盖手机版。
- 本次未修改游戏逻辑、资源或测试断言；新增的仅为测试执行器、隔离配置及测试报告。

## 需要优先处理的交互问题

### 怪物意图与后排悬停不稳定

原生验收出现“从主怪移动到后排后，提示内容未保留”“状态刷新后静止鼠标的提示未保留”“随机 Buff 说明未显示”等失败。菜单关闭后的悬停恢复检查也出现过失败与通过不同结果。必须结合两轮矩阵判读，不应直接忽略，也不能在未排除窗口焦点／原生指针时序影响前断言是确定的游戏逻辑错误。

重点入口：`tests/monster_intent_native_selftest.gd`、`tests/monster_intent_hover_selftest.gd`；生产实现：`ui/battle/monster_intent_strip.gd` 的 `_process`、`ui/battle/battle_test_scene.gd` 的 `_show_intent_tip`／`_hide_intent_tip`。

`primary_occlusion_selftest` 与 `three_enemy_fixed_layout_selftest` 也出现过后排实体原生 hover 命中失败，同一项目存在通过／失败波动。意图、遮挡和布局验收存在提前结束的情况，后续未执行的原生交互不能算作已覆盖；各轮的布局、召唤和多动结果必须分别判读。

## 音频与资源包限制

- 运行中多次出现 Wwise `Selected media 0 not available`。SoundBank 初始化及加载成功不代表每个事件都有可用媒体；需要另做资源配置检查及实际听感验收。
- 音频测试页 `tests/audio_test/audio_test.gd:422` 的 `_refresh_status` 将 Callable 传给 `Array[Dictionary].count()`，触发类型校验错误。`count()` 不接受谓词；该页虽然限时启动检查退出为 0，也不能算无错误启动。这是音频调试页问题，不是事件队列生产逻辑错误。
- 250 个非超时进程均出现 ObjectDB 退出泄漏警告，包含启动检查；另有少量资源仍在使用的退出错误。需要定位共享启动／退出清理链，不能因为退出码为 0 就忽略。当前未做长时压力测试，不能据此推算持续运行中的泄漏速度。
- 怪物 TXT 资源包用例使用本次生成的最小测试 PCK（CSV 加 23 份实际 TXT），不是正式发行导出包。它仅验证这组文本可以被打包并读取；项目当前没有可直接沿用的导出预设，因此没有验证 APK／EXE 正式打包。
- 资源包检查出现过超时，已限时终止并保留日志，必须结合第二轮结果判断稳定性，不能将超时当作通过。
- 桌面版资源包检查两轮均超时；Android 同项结果见矩阵。两端生成的最小 PCK 的 SHA256 相同，不能简单归因于两端 TXT 内容不同。

## 未覆盖与建议顺序

Android 验证是在 Windows 上运行独立手机工程，并注入触屏事件；未覆盖真实 Android 设备、ARM 原生插件、APK 安装、系统返回键、不同厂商 GPU 和实际触屏手感。未开展长期性能／内存压力测试，也未人工听完全部音频。

建议先处理可见的意图／后排悬停不稳定，再修复旧测试及工具加载入口，清理音频资源报错，然后重新执行同一清单。不要根据旧断言把四层、6／3／3、20 格棋盘或新增奖励改回旧版本。
