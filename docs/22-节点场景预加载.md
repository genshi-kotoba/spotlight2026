# 节点场景预加载

## 行为

- 主菜单出现后，后台预加载地图入口、战斗公共场景、商店和奖励界面组件。
- 每次进入或读档恢复一层地图，为这层的**全部节点**登记资源清单，不限于已探索或邻近节点；普通、精英、Boss、商店和事件都包含在内。
- 战斗节点提前加载本层背景、已按种子分配的怪物图片与 TXT 台词，以及卡牌、Buff、动态界面所需资源。优先沿用局内保存的怪物资料，并与战斗相同按图片路径匹配台词，兼容旧编号。
- 商店提前加载公共商店界面和候选卡图，也覆盖附魔选牌和奖励开包；不提前生成或保存货架，不改变购买、刷新或种子规则。
- 目前事件节点使用地图内已经创建的占位弹窗，不存在独立事件场景，清单覆盖其公共地图资源。将来制作专属页面时，在预加载器对应分支增加路径即可。
- 玩家靠近、选中节点后，将该节点的待加载资源提到队首。相同场景、卡图和怪物图片只保留一份。
- 击败 Boss 后，领取奖励期间即启动下一层全部节点资源预热，不必等返回地图才开始。

## 调度与生命周期

`autoload/scene_preloader.gd` 注册为 `ScenePreloader`。使用 `ResourceLoader.load_threaded_request` 读取场景及资源，最多两个请求同时在途；每帧只收取一个已完成任务，调度预算 1.5ms。单个已完成资源的提交成本无法硬切分，这个预算不是主线程帧耗时上限。小型 TXT 按帧读取并缓存，`TextCatalog.read_text` 自动复用，仍保留参数替换和修改时间失效检查。

强引用保证资源在离开节点后不会立刻被释放，再次进入时无需重新读盘。只保留公共场景和当前层专有资源；换层、新局、切换档案时清理旧节点清单，不会为每个节点实例化一个战斗。旧层仍在途的请求正常收尾，但不将不再需要的结果写回缓存。

背景路径仍由 `battle_environment.gd` 统一维护，改为按层取图，避免一加载战斗脚本就同步读取四张大背景。

统一转场服务直接复用预加载缓存。若玩家过快进入节点而后台尚未完成，提升同一个请求的优先级并等待，不额外启动一份加载；原有变暗、操作锁、准备完成检查、失败恢复和连续跳转逻辑保留。

此缓存不进入存档，不实例化玩法场景，不触发 `_ready`，不抽牌、不生成敌人、不消耗玩法随机流、不开放未探索区域。地图三层进度及第四层暂未开放的规则不变。商店的选牌渲染也改为一次加载定义，避免每展示一张卡都重新解析整份 CSV/JSON。

## 验证及性能观察

- `tests/scene_preload_selftest.tscn`：四层全部节点资源清单、去重、热缓存、TXT、换层/在途任务清理、状态与随机隔离、无存档写入、缺资源和真实热转场。
- `tests/world_encounters_selftest.tscn`：三层真实节点、战斗、读档、Boss 换层、奖励及失败返回。
- `tests/scene_transition_selftest.tscn`：加载遮罩、输入锁、重定向和失败恢复。
- `tests/shop_enchantments_selftest.tscn`、`tests/map_ui_merge_selftest.tscn`：商店、附魔和真实 UI 流程回归。

`ScenePreloader.stats()` 提供节点数、后台队列、在途请求、资源命中等统计，`node_status(map_id, node_id)` 查询单节点准备状态，不在玩家 UI 显示隐藏敌人。

`SceneTransition.last_metrics` 分别记录资源等待、实例化/准备和整体转场耗时。预加载消除的是可提前完成的资源等待；初次地图生成、界面布局、开局结算及首次渲染仍需执行，不能等同于零耗时或承诺固定加载时间。
