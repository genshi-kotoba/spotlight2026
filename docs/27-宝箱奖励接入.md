# 宝箱与残堆奖励接入

依据 2026-10-19 实时读取的飞书《策划案》（文档 ID `MxLpdnuukoTEhcxtxadcfu1Wnab`）：“宝箱：获得一定银币/随机药水；残堆：获得一定银币/随机残片”。本次分别实现两种节点，不把残片加入宝箱池。新局首层保留原八节点并额外新增一个残堆：3 普通战斗、1 商店、1 宝箱、1 残堆、2 随机事件、1 Boss，共九节点；残堆不计入随机事件池。战斗残片包与已实现随机事件来源保持。

## 当前测试配方

策划案未注明银币数量与两类奖励权重。`data/config/node_loot_rewards.json` 分 chest / pile 配置。每种节点的两类奖励权重各 1：宝箱为 50% 获得 100–200 银币（含两端），50% 获得一瓶随机药水；残堆为 50% 获得 100–200 银币，50% 直接获得一个随机组合残片。主能力为 21 条正式触发／效果之一，独立随机名称与颜色，并附加 70% 负面／30% 在场词条；详见 docs/28-残片随机生成与范围连锁.md。旧封存残片编号仍可读取，不重抽。四种现有药水等概率，名称与现有背包/战斗使用规则一致。数量与权重为可配置测试值，不作为最终数值定案。

## 正式入口与事务

地图靠近宝箱或残堆按 E，`menu_map_entry.gd` 打开 `NodeLootPopup`。打开先封存本箱奖励并保存，不发奖；“稍后领取”取消当前请求、保持节点未完成，封存结果保留。下次到访或读档继续同一奖励。

“领取”一次领取本箱全部奖励：物资入包、领取记录和地图节点完成在同一次 `SaveGateway.save_current()` 中写入同一档案。成功后箱体按既有完成表现淡出、实体占地释放；“继续探索”只关窗口，不再二次结算。保存失败恢复物资、Session 与 PlanarMapRun 楼层缓存，仍可原地重试或关闭；恢复 Session 会轮换 request_id，弹窗必须同步新令牌。

| `RunNodeLoot` 接口 | 约定 |
| --- | --- |
| `generate(seed, map_id, node_id, floor_index, source_kind="chest") -> Dictionary` | source_kind 仅 chest/pile；纯奖励生成，用于预检；不发奖、不调用全局 begin_run。失败为空字典。 |
| `open(run, request) -> Error` | 校验当前真实请求，封存并保存；已存在未领结果复用，已完成或已领取拒绝。 |
| `record(run, request) -> Dictionary` | 返回记录深拷贝，仅作显示，不能直接写回来当成领取。 |
| `claim(run, request) -> Error` | 同步完整事务，成功后地图装配同步视图及结算信号；重复、失效或跨层请求拒绝。 |
| `cancel(run, request) -> Error` | 取消未领取请求并保存，不消耗箱子。失败不关闭窗口。 |
| `valid_records(value) / valid_map_records(records, floors) -> bool` | 分别校验记录结构和已保存地图的来源/完成状态一致性。 |

业务调用限制：仅当前 `SaveGateway.current_run()`、活动局、无战斗和战斗待领奖、当前地图/楼层且完整 `request == Session.pending` 的宝箱/残堆可调用。UI 的按钮禁用不是防重依据。模块不通过通用 `node_result_submitted` 模拟发奖；请使用正式地图接线。

## 随机与存档合同

用独立 `SeedRegistry(main_seed)` 派生 `REWARD / [source_kind + "-loot-v1", map_id, node_id]`。同主种子和同节点结果固定，换开启顺序不影响；不同楼层的同名节点地址不同。此局部派生不重置或消费全局地图/战斗随机流。

本局 `inventory_state.node_loot` 为可选扩展，字典 key 是 `JSON.stringify([map_id,node_id])`；记录包含 `version=1,map_id,node_id,floor_index,source="chest"或"pile",entries,claimed`。物品 item_id 也来自同一稳定地址，不含请求令牌或时间。首次开启后以封存 entries 为准，修改配置不重抽已封存箱子；药水消耗后不会因为背包已无物品而再次发奖。

RunStateMachine 在恢复时校验扩展结构；SaveGateway 在安装档案前校验来源节点存在及 `claimed == 地图 completed`。非空领奖记录要求同档存在地图检查点；损坏记录拒绝读取，不静默重建或再次发奖。

不升级旧存档版本，缺 `node_loot` 的旧档继续可用。旧 Demo 若已将宝箱标为 completed 但没有奖励记录，保持已消费状态，不自动补发。新的未完成宝箱可以走正式奖励入口。新局首层使用 `content_profile="alchemy_floor1_pile"`（events=5），原 `alchemy_floor1`（events=4）保持原样。已有八节点存档不补插残堆、不改变几何和指纹；需新局查看新增残堆。无需重开种子系统或重建已有地图。

## 窗口关闭保存

正式装配由 SaveGateway 独占窗口关闭保存，避免 GlobalState 先写不含地图的裸档、随后补写失败而丢失检查点。`GlobalStateMachine.save_on_window_close` 默认 true，保留独立使用行为；SaveGateway 在装配时将其设为 false，统一写完整档案，失败留在游戏中。此变更不承诺断电恢复能力，也不改动存档格式版本。

## 验证入口

专项脚本、独立档案、截图与构建包均在仓库外；覆盖真实 E 交互与鼠标领取、关闭重开、保存失败重试、防重复、冷恢复、战斗残片包打开/刷新/装备/读档，残堆直接残片装备及读档，以及正常窗口退出后的继续。测试结果按实际原生记录交付，不用静态接口检查代替运行验收。
