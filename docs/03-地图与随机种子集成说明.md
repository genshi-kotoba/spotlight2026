# 地图与随机种子集成说明

本文说明 `PRG-005 随机种子` 与 `PRG-011 地图系统` 合并后的调用边界。

## 一、完整流程

1. `GlobalState.start_new_run()` 创建 `RunStateMachine`；局内状态机在新游戏时只调用一次 `SeedService.begin_run(seed_text)`，并保存返回的最终主种子。
2. 地图实例取得稳定 `map_id`，例如 `map-001`。
3. 地图取得 `SeedService.get_stream(RandomDomains.MAP_NODES, [map_id], occurrence)`。
4. `MapNodeDistributor.generate_first_map()` 在手写地形的可达格上生成 `MapNodePlan`。
5. `MapScene` 首次生成后调用 `RunStateMachine.set_map_node_plan()` 保存计划；重新打开地图通过 `get_map_node_plan()` 恢复，不再次生成。
6. `GlobalState.save_game()` 同时保存局内业务数据和 `SeedService.capture_snapshot()`。`continue_saved_run()` 先恢复随机快照，再安装局内／战斗状态。

角色到达一个已分配节点时，`MapScene.map_node_entered(node_id, kind, coord)` 会发出信号。事件、战斗和商店装配层监听该信号进入对应流程，不需要反查画面节点。

演示场景在没有活动局和随机上下文时使用导出属性 `demo_seed_text` 启动演示随机上下文。正式流程已经初始化或恢复随机上下文时，它不会重置主种子。

角色落到节点后，`MapScene` 会把 `visited` 与节点 `kind` 写回当前 `RunStateMachine`；写回失败时停止派发 `map_node_entered`，避免画面已经进入节点但存档状态没有更新。

## 二、当前地图规则

- 地形保持手写模板，种子不随机改变高度、墙体或通行规则。
- 节点候选只来自起点可达、地形可通行且不是起点的格子。
- 第一张地图固定 3 个普通战斗、1 个精英、1 个 Boss，并随机生成 7 至 9 个事件节点。
- Boss 从离起点最远的两圈中抽取。
- 节点稳定 ID 为 `hex:q,r`；其他系统应保存这个 ID，不能使用节点对象地址或场景实例 ID。

## 三、复现与隔离

相同的主种子、内容版本、地图 ID、`occurrence` 和候选地形会得到相同节点计划。地图使用 `map.nodes` 独立流，因此商店、奖励或战斗流先消费多少随机数都不会改变地图。

`get_stream()` 返回持续推进的同一条流。已经生成的地图计划必须保存；重复执行生成代码会取得这条流后续的随机数，而不是自动返回旧结果。

### SeedService 接口

| 方法 | 作用 |
|---|---|
| `begin_run(seed_text)` | 新建随机上下文并清空旧流；只有单局协调者调用 |
| `get_main_seed()` | 读取当前最终主种子 |
| `get_stream(domain, ids, occurrence)` | 按稳定地址取得并缓存一条持续推进的流 |
| `capture_snapshot()` | 捕获主种子和所有已创建流的精确进度 |
| `restore_snapshot(snapshot)` | 完整验证后原子恢复随机上下文；旧流句柄失效 |

`RandomStream` 提供左闭右开的 `int_range()`、等概率 `pick()`、权重抽取 `weighted_pick()` 和使用本流的 `shuffle_in_place()`。业务代码不要再调用全局 `randi()`、`randf()`、`Array.shuffle()` 或 `pick_random()`。

## 四、扩展方式

- 新增地形模板时，通过 `map.layout + [map_id]` 选择模板；不要与节点分配共用一条流。
- 第二、第三张地图应新增各自的配比配置或生成器入口，不修改第一张地图的固定常量。
- 商店节点加入 `MapNodeKind.SHOP` 后，应由地图节点流只决定位置；商品内容使用 `shop + [map_id, node_id]` 独立生成。
- 美术图标到位后替换 `MapNodeView`，不要把表现资源写进 `MapNodePlan`。
