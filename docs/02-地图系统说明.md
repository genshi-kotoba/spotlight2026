# 地图系统说明

本文说明 `systems/map/` 这个模块怎么用。对应程序资产 `PRG-011 地图系统`。

面向要改地图、加节点类型、或者接 PRG-018 地图界面的同学。

---

## 一、这个模块做什么

在 Godot 3D 里呈现一张平顶六边形地图，并处理三件事：

1. **地形** —— 不同高度的地块、墙体、山脊山谷
2. **通行** —— 哪些格能走，怎么寻路
3. **表现** —— 相机、路径预览、走过的格子熄灭

地形模板是**手写在编辑器里的文本**；战斗、精英、Boss 和事件节点由主种子确定性分配。理由与边界见第五节及 `docs/03-地图与随机种子集成说明.md`。

## 二、文件职责

一个文件一件事，改哪里找哪里。

| 文件 | 职责 |
| --- | --- |
| `hex_coord.gd` | 平顶六边形的坐标数学。轴向存储、立方运算。纯静态函数，无节点依赖 |
| `map_tile.gd` | 单格数据。坐标、高度、地形 |
| `map_terrain.gd` | 地形表。每种地形带通行标记与颜色 |
| `map_layout.gd` | 文本布局的解析、通行规则、寻路入口 |
| `map_pathfinder.gd` | BFS 寻路与可达集合。不持有地图数据，通行判定由调用方传入 |
| `map_mesh_builder.gd` | 按高度生成棱柱网格，只画暴露的面；高亮边框与数字底片也在这里 |
| `map_builder.gd` | `@tool` 节点。把布局文本变成网格，编辑器里改字符就重建 |
| `map_highlight_pool.gd` | 一组格子高亮边框，池化复用。路线与光标各持一个，互不干扰 |
| `map_tile_label.gd` | 贴在格面上的数字池，路径预览用 |
| `map_path_view.gd` | 路径显示。组合路线边框、路线数字、光标三层 |
| `player_mover.gd` | 沿路径逐格移动 |
| `map_camera.gd` | 可调视角相机，带平滑跟随与边界限制 |
| `map_input.gd` | 鼠标拾取。物理射线打真实几何 |
| `map_scene.gd` | 装配点。子节点彼此不认识，全部在这里接线 |
| `map_node_kind.gd` | 稳定的节点类型枚举、占位标记与颜色 |
| `map_node_plan.gd` | 应写入局内存档的地图节点分布及稳定节点 ID |
| `map_node_distributor.gd` | 使用注入的 `RandomStream` 分配地图节点 |
| `map_node_view.gd` | 节点占位表现；正式图标到位后替换本层 |
| `map_demo.tscn` | 演示场景 |

分层依赖是单向的：装配层认识各组件，组件之间不互相认识。相机不认识地图，路径显示不认识角色，全部由 `map_scene.gd` 注入。

## 三、在编辑器里摆地图

选中场景里的 `MapBuilder` 节点，编辑 `Layout Text` 属性。它标了 `@tool`，**改一个字符网格立刻重建**，不用运行游戏。

一个字符一格，行号为 row、列号为 col。

| 字符 | 含义 |
| --- | --- |
| `.` 或空格 | 无此格 |
| `0` 至 `9` | 平地，高度层级 0 至 9 |
| `A` 至 `Z` | 平地，高度层级 10 至 35 |
| `r` | 石板路，高度 1 |
| `#` | 墙体，高度按周围地形推断 |
| `@` | 起点，高度强制为 1 |

几处不显然的约定：

**数字是层级，不是世界高度。** 一层在世界里有多大由 `Step Height` 决定，默认 0.25。所以字符 `K`（20 级）对应世界高度 5.0。

**墙的高度不写死。** 井号的高度取周围可通行邻格里最常见的那一层。若写死成固定高度，把它放进高地会凹出一个坑：视觉上像陷阱而不是墙，通行判定还会被高度差顺带挡掉，把「地形阻挡」这条规则整个掩盖住。

**起点的高度是强制的。** `@` 一律记作高度 1。外部工具若自己维护一份地图数据，必须跟着这条规则走，否则算出来的可达性和引擎对不上。

**缩进会被剥掉。** 源码里顶格或缩进写都行。

## 四、通行规则

能不能从一格走到相邻格，由 `MapLayout.can_move(from, to)` 判定，两个条件同时满足才可通行：

```
1. 目标格地形 passable
2. |height[to] - height[from]| * step_height <= CLIMB_LIMIT_WORLD
```

| 常量 | 位置 | 取值 | 含义 |
| --- | --- | --- | --- |
| `CLIMB_LIMIT_WORLD` | `map_layout.gd` | 0.5 | 允许爬升的世界高度上限 |
| `STEP_HEIGHT` | `map_layout.gd` | 0.25 | 一个高度层级在世界里的尺寸，默认值 |
| `step_height` | `MapBuilder` 导出属性 | 0.25 | 实际生效值，编辑器里可拖 |

**限值说的是世界高度，不是层数。** 这两件事必须分开：`step_height` 是视觉参数，随手可调；若把限值写成「能上几级」，拖一次台阶高度就静默改掉了玩法。所以判定时统一换算成世界高度再比，`MapLayout` 从构建方拿到当前生效的 `step_height`。

按默认值，两级以内能上，三级开始拦。

**上下对称。** 下降受同一限制，避免出现「掉下去上不来」的单向陷阱。

**寻路用 BFS，不用 A\*。** 没有行动点，所有可通行边代价相同，图是无权的。A\* 的启发式在无权图下退化为 0，加权逻辑与方向代价都是死代码。

## 五、手写地形与随机节点的边界

`PRG-011` 的需求里有节点配比（第一张图 3 普通敌人 + 1 精英 + 1 BOSS + 7 至 9 事件节点，从池中随机取），那是**每局开局时的节点分配**，属于 PRG-003 局内状态机。

**地形本身走手写。** 程序化生成的随机地形很难同时满足三个要求：峰顶都上得去、只有几条小路能通、不可达的只剩零星孤格。当前这张演示地图是靠「缓底图 + 陡锥峰 + 螺旋小径」这个明确的结构做出来的，不是靠调随机参数撞出来的。

**节点分布走种子。** `MapScene` 从 `SeedService` 取得 `map.nodes + [map_id]` 对应的独立流，`MapNodeDistributor` 在起点可达区域里分配 3 个普通战斗、1 个精英、1 个 Boss 和 7 至 9 个事件；Boss 限定在离起点最远的两圈。相同主种子、地图 ID、次数和版本会得到相同分布，商店或战斗随机不会干扰它。

要换地形，改 `Layout Text` 即可。要有更多地图，可把布局文本抽成资源，并用 `map.layout + [map_id]` 选择模板；地图节点仍使用独立的 `map.nodes` 流。

## 六、操作方式

| 操作 | 效果 |
| --- | --- |
| 鼠标悬停 | 显示到那一格的路线，每格标出还剩几步，终点为 0 |
| 左键点击 | 角色沿路线走过去 |
| 中键拖拽 | 转水平朝向与俯仰角 |
| 滚轮 | 缩放 |
| Q / E | 水平旋转 |
| R / F | 俯仰 |

俯仰方向与常见三维软件相反：往下拖抬高俯视角。这是照手感定的，不是笔误。

## 七、关键参数

都在对应节点的导出属性里，编辑器里可直接调。

| 参数 | 节点 | 默认 | 说明 |
| --- | --- | --- | --- |
| `Step Height` | `MapBuilder` | 0.25 | 一个高度层级的世界尺寸 |
| `Outer Radius` | `MapBuilder` | 1.0 | 六边形外接圆半径 |
| `Tiles Per Second` | `Player` | 6.0 | 移动速度 |
| `Follow Smooth Time` | `Camera` | 0.15 | 跟随收敛时间 |
| `Initial Distance` | `Camera` | 24.0 | 初始缩放 |
| `Mark Unreachable Hover` | `MapScene` | true | 悬停不可达格时是否标红 |
| `Camera Bounds Margin` | `MapScene` | 2.0 | 镜头注视中心能出地图多远 |

`Follow Smooth Time` 与 `Tiles Per Second` 是联动的：角色每格耗时若短于镜头收敛时间，镜头会一直落在后面追。改一个要看另一个。

## 八、自测

```bash
godot --headless --path . --script res://tests/map_selftest.gd
```

覆盖地图构建、高度分层、爬升限值（含世界高度换算的边界）、地形阻挡、上下对称、寻路合法性、可达集合、几何法线方向，以及同种子复现、跨域隔离、节点配比、可达性和 Boss 距离约束。

断言全部从布局里现查特征格，不写死坐标，换演示地图不用改测试。

## 九、已知限制与待办

| 项 | 说明 |
| --- | --- |
| 更多节点规则 | 当前落地第一张地图的普通战斗、精英、Boss 与事件；商店及后续地图配比需追加配置 |
| 迷雾未做 | 策划案要求「只显示能无阻通达区域视野」。`map_pathfinder.reachable_from()` 已经能算出那个集合，接上即可 |
| 多地形模板 | 节点已经接入 PRG-005；当前只有一份手写地形模板，`map.layout` 选模板尚待更多地图资源 |
| 高亮数字尺寸 | 相机拉远时数字会变小（世界缩放）。要固定屏幕尺寸需改用 `Label3D.fixed_size`，但那个模式下 `pixel_size` 语义不同，要重新标定 |
| 渲染后端 | 当前是 Mobile，不支持 SSAO 等基于深度的环境光遮蔽。地形可读性若要再提升，需在顶点色或材质上做文章 |
| 美术资产 | `UI-018 大地图节点图标`、`UI-019 大地图玩家位置` 未交付，当前是占位体 |
