# 召唤怪物同屏与独立血条

## 显示与操作

- 本体固定使用原主立绘和顶部长血条，不再随攻击目标替换；无论召唤数量多少，立绘始终保持场景原始位置、尺寸和缩放。
- 召唤物在本体左右两侧常驻显示，仅随从根据侧边可用空间缩排，有独立的短血条、生命数字、格挡及 Buff 显示。
- 每只召唤物的短血条右侧附带缩小的行动意图，复用本体图标和数字样式：攻击显示伤害，防御显示格挡，其他显示特殊意图。
- 召唤物增多时只调整随从，底部不超过手牌区域上沿；死亡时隐藏意图、血条先用 0.3 秒归零，再淡出退场。
- 移除旧 `EnemyTargetSelector` 切换列表。直接点击场上怪物选择攻击目标，金色框表示选中，嘲讽限制仍由原规则生效。
- 旧列表中的药水操作保留，独立放在左侧 `PotionActions`。

## 代码位置与可调参数

- `ui/battle/battle_test_scene.gd`：`COMPANION_SIZE_RATIO` 控制随从基准大小（520×488 的 80%，不是原始本体的 80%），`ENEMY_LINEUP_AREA` 控制随从区域，`_render_enemy_lineup()` 负责布局和目标选择。
- `ui/battle/enemy_companion_view.gd`：单个召唤物视图；`layout_at()` 控制短血条、意图、名称与 Buff 的位置，短血条最大宽度为 280，意图图标组缩放为本体 UI 的 48%。`_show_intent()` 与本体一样读取当前快照中的首项 `actions`，不另外预演未来随机行动。
- `ui/battle/combat_feedback.gd`：伤害、治疗、格挡飘字和受击动画按具体 `enemy_id` 定位，避免不同怪物共用主立绘反馈。

## 队列和兼容性

保留现有怪物召唤、阶段转换、伤害、嘲讽等业务规则，不修改存档结构。表现队列现在保存整队敌人的深拷贝快照，并记录召唤事件；刷新只显示当前播放的快照，不提前显示逻辑已经算完的后续怪物或血量。死亡后进入下一阶段的本体在闪红期间恢复时，最终颜色读取最新状态，避免残留死亡透明度。

正式地图战斗继承 `BattleTestScene`，同样使用此实现。旧存档中的敌人数组可直接重建场上视图。
