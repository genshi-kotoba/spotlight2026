# 战斗测试场景

场景路径：`res://ui/battle/battle_test_scene.tscn`

典籍系统测试入口：`res://ui/relics/relic_test_scene.tscn`。编排后点击“战斗”保存并进入本场景；
战斗左侧显示典籍布局、触发反馈与生效次数。详细规则见 `08-典籍残片系统与测试说明.md`。

在 Godot 编辑器中打开该场景并按 **F6** 即可单独运行，不会替换项目当前的地图主场景。

## 测试内容

- 1920×1080 测试背景。
- 敌方立绘使用 `CHR-025.png`。
- 自动创建 20 张测试牌；其中 11 张分别覆盖对敌伤害、自伤、格挡、治疗、中毒、
  虚弱、力量、移动指针、抽牌、选择弃牌和重复后一张牌，另外 9 张为效果牌副本。
- 下方手牌、左侧抽牌堆入口、右侧弃牌堆入口。
- 点击手牌后按点击顺序进入右侧出牌区；出牌区卡牌严格使用手牌显示尺寸的 1/2。
- “取消”将全部已编排卡牌退回手牌。
- “结算”使用 `UI-017.png` 从上到下指示当前卡牌，每张停留 0.5 秒。
- “选择弃牌”会暂停指针，玩家点击足量手牌后自动提交并从原位置继续。
- “移动指针”应放在另一张牌之后；它会回退 1 格，使前一张牌再次触发一次。
- 结算后卡牌进入弃牌堆，显示一次怪物回合，再进入下一玩家回合。
- 玩家与 CHR-025 的生命、格挡和 Buff 层数会显示在战场上方。
- 战斗结束明确提示胜利/败北；左侧“重开战斗”可重新进入测试。

## 可调参数

选中场景根节点 `BattleTestScene`，可在检查器中调整：

- `initial_draw_count`：战斗开始时的抽牌数，默认 12。
- `play_limit`：单回合出牌区容量，默认 10。
- `per_turn_draw_count`：后续玩家回合开始时的抽牌数，默认 2。
- `resolution_delay`：每张测试卡的占位结算时间，默认 0.5 秒。
- `enemy_turn_delay`：怪物测试回合的展示时间，默认 0.75 秒。
- `enemy_starting_health`：测试敌人的初始/最大生命，默认 3000，可改为低血量测试终局。

此前“点击手牌无响应”的复现原因是保存的典籍构筑在首抽时就击杀了原本 300 血的敌人；战斗已结束，但 UI 仍展示可点击手牌。现在默认提高测试敌人的血量，并明确终局提示、禁用不可操作的手牌，增加重开入口。保存的典籍构筑没有被修改。

## 实现约束

测试场景复用现有 `CardView`、`BattleStateMachine` 和 `BattleEffectResolver`。战斗逻辑由统一事件队列 + 规则引擎推进到空闲或输入暂停；0.5 秒等待只属于 UI 表现层，不在效果规则中 `await`。交互式弃牌使用显式暂停/提交协议，支持一张卡中多次请求与中途续接。架构细节见 `09-战斗事件队列与规则引擎.md`。

容器刷新经 `call_deferred` 调度，卡牌节点使用 `queue_free` 延迟释放，避免在按钮 `pressed` 信号派发期间释放锁定对象。

效果规则回归测试：`res://tests/battle_effect_rules_selftest.tscn`。

真实鼠标与 UI 交互回归：`res://tests/battle_hand_input_selftest.tscn`，覆盖首抽致死提示、悬停底边、前中后三处手牌点击、半尺寸出牌区、取消与连续弃牌。测试使用独立典籍配置，不覆盖玩家存档。
