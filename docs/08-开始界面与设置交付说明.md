## 二、界面现状

```
开始界面 ──「当前档案 N ▾」──▶ 切换档案 ──「切换档案」──▶ 开始界面
         ──「设置」─────────▶ 设置 ──「返回」──▶ 开始界面
         ──「新游戏」/「继续游戏」─▶ 占位跑图（临时）──「回主菜单」/「放弃本局」──▶ 开始界面
         ──「成就」/「感谢名单」──▶ 底部提示条
         ──「退出游戏」────────▶ 退出
```

开始界面包含：左上标题（当前文字为「这里是标题」）、左侧竖排六个按钮（继续游戏、新游戏、设置、成就、感谢名单、退出游戏）、右上角「当前档案 N ▾」、右下角 `v0.1.0`、铺满屏幕的背景贴图位（当前为空）、底部提示条与居中确认弹窗（默认隐藏）。

| 按钮 | 当前档为空 | 有进行中的局 | 只有记录 |
| --- | --- | --- | --- |
| 继续游戏 | 置灰 | 可点 | 置灰 |
| 新游戏 | 可点 | 可点，先弹「覆盖档案 N？」 | 可点 |
| 设置、成就、感谢名单、退出游戏 | 可点 | 可点 | 可点 |
| 切换档案屏的「切换档案」 | 可点 | 可点 | 可点 |
| 切换档案屏的「删除存档」 | 置灰 | 可点，先弹「删除档案 N？」 | 可点 |

档案卡片三态：空（无存档文件）、进行中（有进行中的局，显示区域与生命、金币；占位局显示进度）、已结束（有文件但没有进行中的局，即死亡或舍弃后的状态，解锁与对局记录保留）。卡片选中描边表示即将切换的档，右下角「当前档案」表示当前生效的档。

### 3.3 方案一：共享 Theme

适用于美术提供不带文字的牌面。六个按钮读取根节点的主题，因此只需配置一次。

1. 新建 Theme 资源，例如 `assets/ui/<编号>/木牌按钮.tres`。
2. 为 `Button` 配置四个样式盒：`styles/normal`、`styles/hover`、`styles/pressed`、`styles/disabled`，类型均为 `StyleBoxTexture`，分别指向初始态、悬停态、按下态贴图；`disabled` 可复用初始态贴图。
3. 按九宫格切图。已有样张为 914×391，可见牌面 841×294，对应 `texture_margin_left = 40`、`texture_margin_top = 53`、`texture_margin_right = 33`、`texture_margin_bottom = 44`。正式资源留白不同时重新测量。
4. 设置 `content_margin_*` 留出文字区域，避免文字压到边框。
5. 将该 Theme 赋给 `main_menu.tscn` 根节点的 `theme` 属性，六个 `Button` 无需改动；需要全局生效时写入项目设置的 `gui/theme/custom`。

### 3.4 方案二：按钮组件

适用于美术将文字绘入牌面的情况。

1. 新建 `ui/components/wood_button/wood_button.tscn`：根节点为 `Button`（`flat = true`），内部叠放 `TextureRect` 显示牌面；三态或用一个 `TextureRect` 按 `mouse_entered`、`button_down` 切换贴图，或叠三个 `TextureRect` 由脚本控制显隐。文字可绘入图中，也可另用 `Label` 叠加。
2. 六个按钮改为实例化该组件，脚本只转发 `pressed` 信号。
3. 每个按钮每态一张贴图，六个按钮共需 18 张。该组件属于公共组件，目录需先登记进 `docs/01-项目结构与目录约定.md`，并修改 `main_menu.tscn` 中的六个节点。

## 四、接入状态机

前置条件：分支 `origin/codex/prg-002-004-state-machines` 合并进 main，`state_machines/`、`autoload/seed_service.gd` 与 `project.godot` 的 `[autoload]` 段由该次合并引入。下列行号指该分支上的 `state_machines/global/global_state_machine.gd`。

1. `[autoload]` 顺序：`GlobalState` 排在 `SaveGateway` 之前。`GlobalState._ready()` 会先按默认路径读档，网关随后读取当前档索引，改写 `GlobalState.save_path`，再调用一次 `load_save()`（幂等重读）。
2. `has_continuable_run()`：`return GlobalState.has_continuable_run()`。
3. `start_new_run(seed_text, config)`：转发。`config` 需提供三张地图；状态机校验 `map_ids.size() == 3` 并拒绝未解锁的初始牌组（`run_state_machine.gd` 的 `_prepare_new_config`）。`main_menu.gd` 的 `_new_run_config()` 当前返回空字典，接入时补齐。
4. `continue_saved_run()`：转发。读档只经此入口，界面不自行恢复随机快照、不重新生成地图节点、不重新洗牌，见 `docs/04-PRG-002-004状态机实现规格.md:211`。
5. `abandon_run()`：转发 `GlobalState.abandon_current_run()`。
6. 删除占位：`PLACEHOLDER_RUN_KEY` 的四处读写（`start_new_run()`、`abandon_run()`、`set_run_progress()`、`read_slot()`）、`set_run_progress()` 方法、`ui/placeholder_run/` 目录；`main_menu.gd` 的 `game_scene` 改指玩法场景。
7. `set_active_slot(slot)`：先调用 `GlobalState.save_game()`，再改写 `save_path` 指向 `user://save/slotN.json`，最后 `load_save()`。`load_save()` 会把内存中的 `current_run` 置空，未落盘的进度会丢失。
8. `delete_slot(slot)`：删除文件后使状态机重新读档，避免其保留已删除的档。
9. `get_setting()`、`set_setting()`、成就存储：保留在网关，状态机内部两份字典保持为空，避免同一设置有多个来源。
10. `quit_game()`：已实现先保存设置、再转发 `GlobalState.save_game()`，最后 `get_tree().quit()`。`quit()` 不触发 `NOTIFICATION_WM_CLOSE_REQUEST`，状态机注册在该通知上的自动存不会执行。
11. 状态机本体不需要修改。

## 五、约束

- 只改 `ui/` 与 `autoload/save_gateway.gd`，不改 `state_machines/`、`systems/`、`core/`。
- 缺素材时按资产编号占位，不自造资源（协作约束第六条）。
- 界面脚本中不得出现 `active_run`，网关中不得对 `active_run` 赋值；`tests/main_menu_selftest.gd` 对此有两条断言。
- 失败路径不调用 `push_error`：网关失败只发 `save_failed` 信号，由底部提示条呈现，避免无头验收日志出现预期内的 ERROR。

## 七、已知缺口

- 全屏与分辨率仅保存数值，未调用 `DisplayServer` 修改窗口；音量同理，音频系统属 PRG-015（第三周）。
- 成就屏与感谢名单页为底部提示条占位，成就在 PRG-020。
- 按钮三态与标题的资产编号待查，接法见第三节。
- 「新游戏」的落点为临时的占位跑图场景，玩法场景到位后修改 `game_scene` 并删除该目录；占位场景不读 run 快照，节点图与战斗的对接在 PRG-017、PRG-018。
- 切换档案屏只有「切换档案」与「删除存档」两个按钮，不切换无法返回开始界面；增加「返回」需先修改规格文档。
- 键盘仅支持 Esc（在占位跑图内返回主菜单），三个界面均无键盘导航。
