# 分层战斗背景

正式地图中的普通、精英和 Boss 战斗共用所属楼层的背景：

| 楼层 | 战斗背景 |
| --- | --- |
| 第一层 | `assets/env/ENV-001/ENV-001.PNG` |
| 第二层 | `assets/env/ENV-002/ENV-002.png` |
| 第三层 | `assets/env/ENV-003/ENV-003.JPG` |
| 第四层 | `assets/env/ENV-004/ENV-004.JPG` |

`ui/battle/battle_environment.gd` 统一维护映射，贴图保持比例、铺满战场，沿用原有裁切、暗化和显示层级，不影响卡牌交互或漂浮文字。

创建节点战斗时，`EncounterFlow` 将开战楼层写入 `battle.player.encounter_floor`，随原战斗快照保存。正式战斗界面读取这个字段，不读取可能已经因 Boss 胜利而推进的当前层数。旧存档缺少该字段时，从本场战斗的 `map_id`（`world:floor-001` 等）恢复；无法识别时回退第一层。不消耗任何玩法随机数。

独立运行战斗测试场景时，可以在检查器用 `test_floor_index`（1～4）预览背景。第四层背景已经可用，但不改变目前仅前三层地图开放的进度规则。

第二层原图是 Godot 不支持的 CMYK JPEG，已转换为 RGB PNG 用于运行。原始 JPEG 和旧导入记录完整保留在 `assets/env/ENV-002/source/`，该目录以 `.gdignore` 排除，避免重复导入失败；其他图片未转换。

验证场景：

- `tests/battle_environment_selftest.tscn`：四层贴图、JSON 保存字段、旧存档回退、独立战斗显示、层级及随机流隔离；图形模式另输出四层截图到 `.godot/`。
- `tests/world_encounters_selftest.tscn`：正式节点战斗、冷读档、三层战斗背景及 Boss 结算后背景稳定性。
