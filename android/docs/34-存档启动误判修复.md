# 存档启动误判修复

## 根因与修改

`SaveGateway._ready()` 会立即校验完整存档。其中 `RunStateMachine._valid_inventory_state()` 调用 `RunShop.valid_shops()`，后者依赖 `TextCatalog` 已加载的卡牌及稀有度资料。

原先 Autoload 顺序是 `SaveGateway → TextCatalog`。只要存档包含已生成商店，首次启动就会在空资料表中查卡失败，返回 `ERR_INVALID_DATA`，封锁继续游戏和新游戏。稍后资料表就绪后，对同一文件再次校验却可成功；不是 JSON 文件被删除或损坏。

修改 `project.godot`：固定为 `GlobalState → MapEvents → TextCatalog → SaveGateway`。TextCatalog 初始化只连接 GlobalState 并读取资料，不在初始化中调用 SaveGateway，因此不会反向依赖。保留严格校验与坏档拒绝覆盖规则，不通过放宽校验、清空物资或忽略存档来绕过问题。未改变存档版本及字段。

## 进度保护

排查开始前，正式主档、备份与旧路径存档已复制到 `.godot/save-rescue-20261019-232943/`。全部读取、新建覆盖、保存及重读测试只写唯一 `.godot/save-recovery-probe-*` 副本。正式玩家文件保持不变，无需用旧备份覆盖当前进度。

## 回归

- `tests/save_crash_recovery_selftest.tscn` 要求 `--source=存档副本绝对路径`，默认 `--operation=resume`；可选 `new` 或 `validate`。不提供源文件则退出，不写正式存档。
- 复现资料表为空时含商店存档验证失败，恢复资料后同一文件通过；检查 Autoload 顺序与首次启动状态。
- 使用实际存档副本进入原战斗，核对生命、银币、牌组副本及附魔、物品、残片棋盘与战斗各牌区；保存、返回菜单、清除内存局状态并重新继续。
- 新建路径经过覆盖确认，只覆盖测试副本；保存后同样重新读取继续。
- `tests/main_menu_integration_selftest.tscn` 增加启动依赖顺序断言，保留覆盖取消、写盘失败回滚、损坏档拒绝与旧布局迁移测试。
- 实际 D3D12/Mobile 渲染及 headless 路径均测试。排查中未复现操作系统级进程崩溃，不将该初始化错误声称为已证实的原生崩溃原因。
