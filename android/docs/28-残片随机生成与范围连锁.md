# 残片随机生成与范围连锁

本次依据 2026-10-19 用户确认的残片设计：新获得残片分别随机名称、颜色和一项触发／效果主能力，再附加一条词条；70% 为负面，30% 为在场。触发残片自行达成条件后重新获得一次空间连锁机会，同一根事件中也允许重新经过它。旧残片、已封存选项和既有存档不重抽。

## 随机生成与身份

`RelicCatalog.generate(rng, primary_id="", auxiliary_id="") -> String` 使用调用者的独立 RandomStream，不调用全局 begin_run。普通主能力池为 10 个触发、11 个效果；残片包先选不同主能力，再生成各自其他属性。名称独立从 23 条非“暂无”的正式名称中选取，与主能力脱钩；颜色独立选八色之一。附属词条先抽 70/30，再在七个负面或五个在场条目中等概率选一项，二者互斥。名称和属性重复合法；物品副本仍由 item_id 区分。

随机来自既有奖励来源地址：战斗包以包身份和刷新轮次，残堆以地图和节点身份，随机事件以节点及选择身份派生。新生成都走同一构造入口。策划本身明确“带负面残片”的海螺选项仍强制负面；其余正常来源用 70/30。

新 ID 为 `RF1/主能力编号/名称来源编号/颜色索引/附属编号`，仅允许表内对应类别和合法颜色索引；不能在存档中塞动作脚本或任意参数。`RelicCatalog.resolve(id, definitions={}) -> RelicFragmentData` 是读取入口；不要再直接用固定 catalog[id] 查运行中残片。旧 FRG、测试编号和基础ID~负面ID仍可读取。ID 包含已抽定的组合，恢复时不消耗随机数。未来若改变数据含义，需新前缀／内容版本，不能复用编号改写旧含义。

`compose(primary_id,name_id,color_index,auxiliary_id)` 用于明确组合的工具／验收夹具，仍经过相同白名单校验。正式新掉落使用 generate。配方保存在字符串，不新增第二套存档数据库。

## 界面与装配

`RelicFragmentData.tint()` 返回该残片持久颜色；`rich_description()` 与 `rich_text()` 生成转义后的富文本，负面红色、在场蓝色。正式典籍填色随残片，不再跟随格子棋盘奇偶。背包、拖拽影子、典籍悬停、残片包、残堆及随机事件残片条目使用相同定义。普通文字不启用 BBCode。

Tab 在地图可拖入典籍、替换、交换和拖回背包；右键／Shift 点击卸下。容量已按后续用户确认更新为20格、正式初始开放9格，本轮隔离测试开放12格，详见[素材装配与封锁格接口](29-残片素材装配与封锁格接口.md)。仍走 RunRewards 的物品事务，保存失败回滚。战斗中只读构筑，不允许改装。没有装备的残片和附属词条不生效。

## 范围连锁合同

- 主触发条件满足时，该格先补回一次“被空间连锁激活”的机会，并产生一次自身触发。
- 自身触发和空间连锁触发都按该残片定义的范围扩散：效果格执行效果；触发格不检查其自身条件，只检查是否还有一次连锁机会。
- 触发格被空间连锁排队时立即消耗机会，避免两个父格重复花费同一次机会。被空间连锁本身不补回机会。
- 机会属于整场战斗。新的根事件、回合开始都不自动补回；只有该格自己的条件再次满足才补回，最多保留一次，不累计。
- 因而 A→B→A 可以在有限机会内返回。某个实际效果又满足 B 的自身条件时，B 在同一根事件内也可重新获得并消耗一次机会。

扩散走统一 BattleRuleEngine 队列，不使用递归或 UI 中第二套结算。`relic.propagate` payload 为 cell/chained/target；`relic.activate` 的 presence 区分附属在场动作。`trigger_activated(cell,chained)` 供展示和只读观察，`fragment_activated` 保留原效果通知。

`battle.player.relic_runtime.chain_charges` 以格子字符串为键、严格 bool 为值；战斗安全边界存档保留已花费的机会，重新接入不能补满。旧存档没有此字段则初始每格一次。单根事件最多 128 次效果、512 次扩散，触顶停止该根事件后续扩散并通知 UI；战斗终局也停止，不把这种安全保护当作正式平衡规则。

附属在场效果独立于主能力：例如“每回合一次弃牌机会”无需激活旁边的效果就生效；其他主触发／效果仍照常工作。触发型上的“触发时…”负面每次扩散算一次，不按相邻效果数量重复惩罚。自然开局／回合补牌不触发获得卡牌类典籍，沿用此前已确认规则；效果抽牌仍触发。

## 验收与正式边界

独立原生验收地图及自动化脚本放在仓库外的 `output/relic-random-chain-native-20261019`。只在隔离构建替换地图入口脚本，正式项目配置、正常战斗节点一次完成和奖励防重规则不改。

验收地图预置空典籍与八枚明确标注的测试背包残片，包含红负面／蓝在场组合。预设 A→B→格挡使用真实 RunRewards 装配；A 为弃牌四邻，B 为每五攻八邻，格挡效果放在 A 范围外。通过真实弃牌可检查 B 未达五攻却空间中继。

指定战斗领取奖励回图后，仅在夹具内恢复该次战斗前地图状态；战斗序号、奖励账本、所得物资和随机状态保留。下一次进入获得新的正式 battle_index，不清空防重复表。夹具提供定位和满血工具，不能把传送与调试胜利当作全地图步行或战斗平衡验证。
