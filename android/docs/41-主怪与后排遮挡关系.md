# 主怪与后排遮挡关系

2026-10-20用户要求：后排怪物的模型、特效、血条、文字都不许遮挡主怪。保留道路站位、中型后排和原始Boss/精英尺寸。

原实现只按组件类型分层，所有模型局部Z=-2，状态图标Z=12/13，飘字与特效全局Z=60/55；后生成的随从模型也会画在主怪模型前。只调整模型顺序无法同时处理血条和反馈。

改为按实体划分互不交叉的层级段：

| 内容 | 有效Z |
| --- | --- |
| 背景、暗层 | -100、-90 |
| 后排模型/光晕 | -82 |
| 后排血条、名字、意图、状态、盾 | -80至-67 |
| 后排伤害/治疗/格挡特效与飘字 | -65 |
| 后排目标箭头及状态悬浮说明 | -64 |
| 主怪模型/光晕 | -22 |
| 主怪血条、名字、意图、状态、盾 | -20至-7 |
| 主怪特效、飘字、目标箭头及状态说明 | -5、-4 |
| 主怪战斗文本、普通UI/手牌 | -1、0及以上 |

EnemySlot统一提供本实体反馈层，宿主enemy_view按实体ID返回；CombatFeedback在真实受伤/治疗/格挡事件创建飘字和VFX后使用对应层级。玩家反馈保留55/60。未知敌方实体的反馈保守落后排层，不能落回全局高层。主怪身份不会因为选中目标、召唤、死亡补位、快照回放和视图重建改变。

绘制顺序和鼠标顺序不是同一机制。主怪槽在GUI树中处于后排槽之后，主怪命中范围使用缓存的纹理alpha位图，并按KEEP_ASPECT_CENTERED的实际绘制矩形换算；不透明身体及自身HUD优先命中，透明区域能选中后排。死亡或受嘲讽限制等不可选择主怪不会挡后排输入。纹理alpha缓存每个主怪贴图只构造一次，不在每帧复制图片。手牌的输入区域继续排除在敌方点击高度之外。

没有修改怪物机制、召唤上限、存档格式、RNG或伤害计算。本次原生测试、真实怪物图和确定性像素对照分开记录，见 `output/primary-occlusion-20261020/verification/`；数字层级检查不能单独证明最终画面。既存Wwise模块缺失诊断单列，不作音频验收。

参考：[Godot CanvasItem层级与输入](https://docs.godotengine.org/en/stable/classes/class_canvasitem.html)、[Control自定义命中范围](https://docs.godotengine.org/en/stable/classes/class_control.html)、[BitMap alpha掩码](https://docs.godotengine.org/en/stable/classes/class_bitmap.html)。
