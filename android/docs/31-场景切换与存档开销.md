# 场景切换与存档开销

将 `spotlight2026-main（to be fusion）` 的优化定向整合至现有 main。优化版基于较早快照，不整目录覆盖，不恢复已经删除的三存档槽、档案选择页或旧图鉴布局；现有抽牌飞行动画、单存档确认覆盖、事件队列、残片和奖励系统均保留。

## 地图首次绑定与恢复

`ui/world_map/flat_2d/map_demo.gd` 新增 `_initial_state() -> Dictionary`，默认返回空字典。首次调用顺序为 `_initial_snapshot()`、`_initial_state()`、`load_map(snapshot, state)`。

正式入口 `ui/main_menu/menu_map_entry.gd` 在读取地图检查点后直接返回 `_saved_entry_state`，不再在 `super._ready()` 之后重复 `load_map()`。因此冷启动或战斗／事件返回地图时，第一次绑定就是实际角色位置、探索和节点状态，不先绑定出生状态再恢复。真正的换层仍按原流程加载新层。

地形、迷雾和全部揭雾状态的准备仍必须完成；不通过提前放开输入缩短表面等待时间。同层纯显示缓存继续由 `MapPresentation` 管理。

## 存档载荷

`GlobalStateMachine.build_save_payload() -> Dictionary` 返回 `{"error": Error, "payload": Dictionary}`，构建完整原有字段并捕获活动局的随机快照，不写盘、不更改保存路径、不发送失败信号。调用方必须检查 `error`。

`SaveGateway.save_current()` 取得载荷后附加地图检查点，执行一次原子写盘。现有 main 已去掉 `.menu-staging` 二次读写，本次不引回该流程。仅成功写盘后更新内存检查点、清除状态机保存错误并发送 `save_changed`。

保留 `capture_save_data()` 作为现有调用方的兼容包装；独立 `save_game()` 使用同一载荷构建方法。单存档路径仍是 `user://save/game.json`，新局独立 RNG 预备、覆盖失败回滚、旧档首次迁移和局外解锁保留机制不变。

## 转场

合入约 0.12 秒淡出／0.16 秒淡入，仍保留 main 的中央加载提示。整个过程锁定输入，准备和连续跳转完成后才淡入，淡入结束才恢复操作。淡入期间不再接收准备阶段重定向，失败路径同样恢复画面和操作。

耗时分资源、场景准备和两段淡化记录；不将动画称为计算提速。详见 `20-统一场景加载提示.md`。

## 随机事件返回

普通事件结果页增加 `EventReturnNow`（“返回地图”），保留两秒后自动返回。玩家可跳过阅读时间，但这不代表资源加载提速。赌博事件原有继续／结束操作保留。

`_finish()` 只接受 `result` 阶段，并先使旧计时器失效。按钮连点与自动计时同时到达也只确认一次；奖励及结果保存仍走 `RunRandomEvents` 事务，失败时允许重试。

## 生成计算

- 平面图局部 BFS 预存按坐标排序的六邻方向，替代每步构建字典和排序。保持邻居访问顺序、完整布局及 RNG 消耗。
- 局部高度细化直接扫描最多三格的峰谷，不构建随后丢弃的大分量诊断。保留坐标、邻接、FIFO、出生点标记及保护格规则。高度是当前受约束生成域内的整数，不作为任意 int64 数据的公共算法。

地图、高度算法版本不变，旧存档无需重新生成地图。

测试存档均放在独立 `.godot` 夹具目录，不修改玩家正式存档。合入前涉及的 main 文件备份于 `.godot/fusion-backup-20261019`，优化版源目录保持不变；本次不提交或推送 GitHub。
