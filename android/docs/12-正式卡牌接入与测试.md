# 正式卡牌接入与测试

## 内容与测试入口

《卡牌表.xlsx》的“卡牌”工作表当前导入70个有效编号。展示属性写入 `data/text/cards.csv`；编号保持原字符串“1”至“70”，不改为图片文件名。空白属性均为“暂无”，解锁状态继续由档案管理。类型为伤害、buff、移位、特殊；稀有度沿用表格的普通/稀有。原表没有被修改。

1–70的已定义效果已接入战斗，61号按确认仅实现5点伤害，附魔继承待接入。新版表已清空71–81号占位行，不再导入图鉴及正式目录；旧JSON中的空指令模板保留但不激活。70号名称已更新为“逆行土星”，保留原有黑色占位图。此次同步29张卡的名称，效果、类型、稀有度与图片路径不变。

重新导入可运行 `python tools/import_cards.py "原始卡牌表.xlsx的绝对路径"`；追加 `--check` 只核对逐字段一致性。脚本只读“卡牌”页，跳过全空尾行，拒绝重复编号、缺号非空行及缺少效果定义的记录；效果文本变化时中止，人工核对并同步事件队列指令后可用 `--accept-effect-changes` 确认导入，避免只改文案而遗漏实际行为。不会改写Excel、其他工作表、效果JSON或玩家存档。

在Godot打开 `ui/battle/formal_card_test_scene.tscn`，按F6运行。左侧下拉框可选择全部1–70或每10张一组；分组模式会全部首抽。默认玩家500生命、1234银币、10个基础牌位，敌人3000生命。牌组、首抽、每回合抽牌、牌位、生命和展示延迟可以在检查器调整。

原 `battle_test_scene.tscn` 的20张测试牌仍保留，不替换主菜单新局配置，不自动解锁正式牌。正式牌测试重开仍进入正式测试场景。编排和手牌悬停复用原卡牌组件，卡面只显示名字与效果文本。

## 统一结算链路

`FormalCardCatalog` 将CSV属性与 `data/cards/formal/programs.json` 中的显式指令合成为 `CardData`，通过 `CardEffectProgram` 和原 `BattleEffectContext` 发出 `action.card_program`。不在运行时解析中文效果文本。

全部指令仍在 `BattleStateMachine.rules` 这一条队列中推进：

```text
card.effect_requested → effect.execute → action.card_program
  → action.damage / block / heal / buff_add / draw / discard_choice
  → 数值规则 → 状态机变更 → 战斗事实 → 被动/典籍反应
  → 原续接点 → 下一效果/下一张牌/下一阶段
```

`FormalCardRules` 注册回合、抽牌、手牌弃置、伤害、跳过与位移规则。它处理牌组能力和指令编排；生命、格挡、Buff、换位、插牌、移除由状态机方法落实。UI只提交选择和播放状态快照，不执行牌效果。

37/62号需要选择弃牌堆，沿用队列暂停/恢复。按点击顺序提交选中的实例ID，检验数量、所在区域与重复ID，然后依次插入当前牌之后。不足要求数量时选择现有全部，空弃牌堆不暂停。32/33/36/38号手牌弃置沿用已有交互续接。

队列保留原50000事件预算与每序列256次指针结算预算。普通回跳源只执行有限次数；失效牌仍占位置，但不再执行效果。重复期间先完成当前牌的重复及位移累计，再失效/续接，不用递归重入来移动指针。

## 已确认规则

- 易伤：正伤害加50%，结果向下取整，每次生效消耗1层。倍率不随层数增长；零伤害不消层。格挡可抵挡放大后的伤害。中毒属于伤害，可受易伤影响；“失去生命”不是伤害倍率效果，不吃力量、虚弱、易伤，也不受格挡抵挡。
- “重复两次/四次”是总共触发2/4次，力量/虚弱在每次伤害执行时重新读取。53号将具备重复能力的牌的总次数再加1。
- 百分比结果向下取整。5/52号比例以实际扣除敌人生命的数值为基数，不把被格挡或溢出生命的数值算作回血/格挡。该比例只作用于当前直接伤害，不泄漏到典籍等派生伤害。
- 前移减小索引，后移增大索引，越界夹到起点/末尾。向后跳过的牌发布 `card.skipped`，46/47/65号响应该事实。42号统计正常推进和主动位移的格数，重复同一位置不算移动。
- 20号保留后一张牌的原位置，空出的前置位置显示空牌位；下回合无需从手牌再次打出即可参与，之后正常入弃。锁牌及空位随合法存档边界保存。
- 68号手牌效果在玩家回合结束触发。69号在打出、手牌弃置、成为最右手牌时触发，自伤后本场移除；同一实例只触发一次。
- 70号移动它自身。左右按本次编排前的手牌顺序判断，伤害发生后更新它的顺序并向左移动一位；它留在手牌时才有效。新抽牌在下次编排时进入这一顺序。

## 其余数值口径

这些口径集中在代码和本节，后续改规则无需改中文文案解析器：

- 力量、虚弱、坚韧为本回合数值修正。坚韧每层使每次获得格挡增加1，与原策划中的格挡修正原语一致。
- 11号按正伤害事实触发，包括格挡抵挡的伤害与中毒；34/35号只响应从手牌弃置，不响应出牌区结算后入弃牌堆。回合清手牌如启用，也属于手牌弃置。
- 54号记录实际生命损失，自伤双倍；67号在敌方行动未造成生命损失时，累加敌方Buff结算前尚存的玩家格挡。记录随卡牌实例保留，洗牌不清除。
- 55号返还本回合总生命损失，含该牌打出前的损失；全敌死亡时在胜负判定清空队列之前执行回血。66号按消耗的格挡计算全体伤害，任一击杀只返还一次原格挡量。
- 51号每1点基础伤害可消耗2点敌方格挡，余下部分扣生命，生命伤害向下取整；无格挡时不额外增伤。
- 次回合额外牌位只在下一玩家回合有效。21号改变当前容量，但不撤销已经确认编排的卡；动态伤害读取修改后的当前容量。62号不占用出牌容量，插入牌仍正常参与结算。
- 43号重复总次数按序列中的非移位牌数量计算；44号本回合允许触发的次数按移位牌数量计算。空牌位不参与两者计数。63号建立当前位置锚点，后续主动位移指向它移动后的实际索引，每次触发与后一张换位。
- 60号银币读取战斗快照中的 `player.silver`，局内开战时由既有 `RunStateMachine.gold` 传入；测试场景单独提供数值。64号复制本回合上一张实际执行的效果指令，不递归复制自身。

## 保存与扩展

回合规则数据保存在 `player.card_rules`，54/67等实例记录保存在卡牌字典；都是JSON安全值。沿用快照v1，旧存档缺少这些可选字段时可正常载入。结算中途或选牌暂停仍不是合法存档边界，不伪造待执行事件恢复。

新增卡牌须同时添加CSV展示记录和JSON指令定义。调整中文文案只改CSV；调整效果参数改指令配置。Buff定义继续放在 `data/buffs/`。不将解锁、附魔或成就规则编码在描述文本中。
