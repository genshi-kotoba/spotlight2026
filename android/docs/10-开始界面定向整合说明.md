# 开始界面与单存档

Godot F5 入口为 `res://ui/main_menu/main_menu.tscn`。地图装配入口为 `res://ui/main_menu/menu_map_entry.tscn`，所有地图、战斗、奖励、商店和种子仍由 main 的正式系统负责。

## 新游戏与继续

- 游戏只维护一份存档，不再提供档案选择、切换或删除界面。
- 没有未完成的游戏时，“继续游戏”置灰，点击“新游戏”直接开始。
- 有未完成的游戏时，点击“新游戏”显示覆盖确认。取消或按 Esc 均保留本局；再次确认才覆盖。
- 覆盖只重置本局：牌组、物资、地图和种子按新局配置重新建立。设置、成就、图鉴解锁与历史保留，旧局以 abandoned 记入历史。
- 覆盖先用独立随机上下文准备新局，验证成功并原子写盘后才提交内存状态。配置无效或写盘失败时，不破坏原文件、内存局、地图检查点和现有随机流。
- “继续游戏”复用内存中的本局；冷启动时从保存的局和随机快照恢复。地图不重复安装随机上下文。
- 地图、战斗中保存返回和退出统一经过 SaveGateway。结算仍在等待输入时不允许保存不完整队列。

## 文件与兼容

唯一正式存档为 `user://save/game.json`，替换写入时保留 `.bak`。存档格式仍为 v1，包含原 GlobalState 的设置、成就、解锁、历史、active_run，以及可选的 `menu_map_checkpoint`。网关一次写入包含地图的完整文件，不再生成菜单索引或临时中间件存档。

第一次升级且新路径尚不存在时，只读旧菜单索引，迁移原来选中的旧存档；无索引时读取旧默认文件 `user://spotlight_save.json`。迁移会验证地图和局数据，复制为新格式路径，不删除或合并其他旧存档。新文件存在后不再读取旧布局。损坏旧存档会给出错误并阻止新游戏覆盖，不静默丢失进度。

旧版三槽位选择页、档案卡、切换/删除/枚举接口及相关信号已移除。仅升级迁移函数认识旧文件名，运行时没有多槽位系统。

## 接口

- `SaveGateway.save_path`：唯一保存路径；测试可设为隔离夹具路径。
- `load_current()`：验证并载入当前保存的数据，不自动进入游戏。
- `has_continuable_run()`、`continue_saved_run()`：查询和恢复未完成游戏。
- `start_new_run(seed, config, overwrite_confirmed = false)`：有旧局且未确认时拒绝覆盖。
- `save_current()`、`abandon_run()`、`quit_game()`：完整保存、主动弃局和保存退出。
- `save_changed`、`save_reloaded`、`run_started`、`run_continued`：无槽位参数的通知。

## 验证

`tests/main_menu_integration_selftest.tscn` 检查单存档菜单、新局/继续、地图与随机快照恢复、取消/确认覆盖、冷启动覆盖、成就解锁保留、错误配置/写盘失败保护，以及旧布局迁移。测试只在唯一 `.godot/menu-integration-*` 夹具目录写盘；图形模式额外输出菜单截图。
